Streamlit은 무엇인가요?

Python 코드로 입력칸·버튼·표·결과 화면을 만드는 라이브러리입니다. 일반 웹 개발의 화면 작성 작업을 Python 함수 호출로 구성하게 해 줍니다.

import streamlit as st
st.title("졸업요건 점검")
이 코드를 읽으면
streamlit을 불러오고, 제목을 화면에 표시합니다.
프로젝트에서 쓰는 이유
이 프로젝트에서는 성적표 업로드와 표 수정, 결과 표시를 담당합니다.
헷갈리기 쉬운 점
Streamlit 자체가 AI 모델은 아닙니다. 문자 인식은 EasyOCR/PyTorch, 학점 계산은 engine.py가 담당합니다.
st는 무엇인가요?

import streamlit as st에서 정한 streamlit 모듈의 별명입니다. Python 예약어가 아니라 개발자가 정한 짧은 이름입니다.

import streamlit as st
checked = st.checkbox("확인했습니다")
이 코드를 읽으면
st.checkbox는 streamlit 모듈 안에 있는 checkbox 함수를 사용한다는 뜻입니다.
프로젝트에서 쓰는 이유
화면 관련 기능임을 짧고 일관되게 나타냅니다.
헷갈리기 쉬운 점
st라는 이름만 쓰면 자동으로 Streamlit이 되지는 않습니다. 먼저 import가 필요합니다. 정확히는 모듈 함수이며 객체의 인스턴스 메서드와 구분됩니다.
import와 from import

다른 모듈이나 패키지의 기능을 현재 파일에서 사용할 수 있도록 가져오는 문법입니다.

import json
from graduation.engine import audit
이 코드를 읽으면
첫 줄은 json 모듈을, 둘째 줄은 engine 모듈에서 audit라는 이름을 가져옵니다.
프로젝트에서 쓰는 이유
화면·OCR·계산을 파일로 나눈 뒤 필요한 기능을 연결합니다.
헷갈리기 쉬운 점
from ... import audit는 audit를 호출하는 것이 아닙니다. 함수 이름을 가져온 뒤 audit(...)를 실행할 때 계산합니다.
as는 별명을 정할 때 사용합니다

import X as Y는 불러온 모듈을 현재 파일에서 Y라는 이름으로 사용하겠다는 뜻입니다.

import pandas as pd
import numpy as np
이 코드를 읽으면
pandas는 pd, numpy는 np라는 별명으로 호출합니다.
프로젝트에서 쓰는 이유
pd.DataFrame과 np.array처럼 자주 쓰는 이름을 짧게 작성합니다.
헷갈리기 쉬운 점
import의 as와 with ... as의 as는 문맥이 다릅니다. with의 as는 컨텍스트 진입 결과를 변수에 연결합니다.
st.checkbox()는 체크박스입니다

체크박스를 화면에 만들고 현재 체크 상태를 bool(True/False)로 반환하는 Streamlit 함수입니다.

advanced = st.checkbox(
    "전공심화 21학점도 별도로 확인",
    disabled=year == 2022,
)
이 코드를 읽으면
advanced에는 사용자가 체크했으면 True, 해제했으면 False가 들어갑니다. disabled 조건이 참이면 조작할 수 없습니다.
프로젝트에서 쓰는 이유
이 코드는 전공심화 추가 검사 여부를 결정합니다. consent 체크박스는 전체 검토 확인에 사용합니다.
헷갈리기 쉬운 점
이수 표 안의 각 행 확인 칸은 st.checkbox가 아니라 st.column_config.CheckboxColumn으로 구성합니다. 전체 확인 체크와 행별 확인은 서로 별개입니다.
with는 특정 작업의 실행 범위를 정합니다

컨텍스트 관리자라는 객체에 진입하고, 들여쓴 구간을 실행한 다음 종료 처리를 맡기는 Python 문법입니다.

with st.sidebar:
    year = st.selectbox("입학연도", [2022, 2023])
이 코드를 읽으면
with 블록 안에서 만든 선택 상자를 사이드바에 배치합니다.
프로젝트에서 쓰는 이유
st.sidebar·st.spinner·st.expander와 PDF 파일 열기 등에 사용합니다.
헷갈리기 쉬운 점
with가 모두 파일을 닫는 것은 아닙니다. Streamlit에서는 화면 영역 지정, PDF에서는 자원 정리처럼 객체마다 진입·종료 의미가 다릅니다. 고급 설명으로는 __enter__와 __exit__ 프로토콜을 사용합니다.
with ... as는 결과를 변수로 받습니다

컨텍스트에 진입했을 때 제공되는 값을 as 뒤의 변수에 연결합니다.

with pdfplumber.open(source) as pdf:
    for page in pdf.pages:
        text = page.extract_text()
이 코드를 읽으면
PDF를 열어 pdf라는 이름으로 사용하고, 블록이 끝나면 라이브러리가 문서 자원을 정리합니다.
프로젝트에서 쓰는 이유
교육과정 PDF의 페이지와 표를 추출할 때 사용합니다.
헷갈리기 쉬운 점
as pdf는 원본 파일 이름을 바꾸지 않습니다. 현재 코드에서 사용할 변수 이름을 붙이는 것입니다.
콜론과 들여쓰기

if·for·def·with 등 뒤의 콜론(:)은 다음에 코드 블록이 시작됨을 알립니다. 들여쓰기로 그 범위를 표현합니다.

if consent:
    result = audit(rows, profile)
    st.write(result)
st.caption("점검 화면")
이 코드를 읽으면
audit와 write는 조건이 참일 때만 실행됩니다. 들여쓰기가 끝난 caption은 조건 밖에 있습니다.
프로젝트에서 쓰는 이유
어떤 조건에서 OCR과 계산이 실행되는지 결정합니다.
헷갈리기 쉬운 점
Python에서 들여쓰기는 단순한 꾸밈이 아니라 실행 의미입니다. 문서의 줄바꿈 정리와 실제 들여쓰기 범위는 구분해야 합니다.
점(.)과 괄호()로 기능을 호출합니다

점은 모듈이나 객체 안의 속성을 찾고, 괄호는 찾은 호출 가능한 기능을 실행하며 인자를 전달합니다.

image.thumbnail((2600, 2600))
st.checkbox("원문 확인")
이 코드를 읽으면
첫 줄은 이미지 객체의 thumbnail 메서드, 둘째 줄은 st 모듈의 checkbox 함수를 실행합니다.
프로젝트에서 쓰는 이유
화면 생성, 이미지 처리, 문자열 정리 기능을 호출합니다.
헷갈리기 쉬운 점
image.width처럼 괄호가 없으면 속성 값을 읽는 것입니다. thumbnail은 객체를 직접 수정하고 None을 반환하므로 image = image.thumbnail(...)처럼 대입하면 안 됩니다.
위치 인자와 키워드 인자

함수 괄호 안에 전달하는 값을 인자라고 합니다. 순서로 전달할 수도 있고 이름=값 형태로 전달할 수도 있습니다.

st.file_uploader(
    "성적표 사진",
    type=["jpg", "png"],
    accept_multiple_files=True,
)
이 코드를 읽으면
첫 값은 화면에 보일 문구입니다. type은 파일 형식, accept_multiple_files는 여러 파일 선택을 허용하는 옵션입니다.
프로젝트에서 쓰는 이유
함수마다 필요한 동작을 옵션으로 설정합니다.
헷갈리기 쉬운 점
인자 이름과 허용값은 함수 정의나 라이브러리 인터페이스를 따라야 합니다. 예제는 설명을 위한 일부 인자만 보여줍니다.
True·False와 체크 상태

bool은 참과 거짓 두 값으로 조건을 표현하는 자료형입니다. True와 False는 문자열이 아니라 Python 값입니다.

consent = st.checkbox("검토했습니다")
if consent:
    result = audit(rows, profile)
이 코드를 읽으면
체크하면 consent가 True가 되고 if 블록에 들어갑니다.
프로젝트에서 쓰는 이유
전체 검토 여부·행 확인·심화 선택을 제어합니다.
헷갈리기 쉬운 점
"False"처럼 따옴표로 감싸면 bool이 아닌 비어 있지 않은 문자열입니다. 보통 조건문에서는 참으로 평가되어 혼동을 일으킬 수 있습니다.
=는 저장, ==는 값 비교, is는 동일성 검사

=는 이름에 값을 연결합니다. ==는 두 값이 같은지 검사합니다. is는 같은 객체인지 검사합니다.

year = 2022
disabled = year == 2022
if row.get("확인") is not True:
    issues.append("원문 확인 필요")
이 코드를 읽으면
year를 저장하고 값이 2022인지 비교합니다. 마지막 조건은 확인 값이 정확히 True가 아닌 행을 찾습니다.
프로젝트에서 쓰는 이유
입학연도 옵션과 확인되지 않은 행 제외에 사용합니다.
헷갈리기 쉬운 점
일반 숫자·문자열의 같은 값을 비교할 때 is를 쓰지 않습니다. 이 코드에서는 True·None 같은 특정 값의 확인에 사용합니다.
st.selectbox()는 하나를 선택합니다

선택 목록을 만들고 선택한 항목의 값을 반환합니다.

year = st.selectbox(
    "입학연도", [2022, 2023, 2024, 2025], index=3
)
이 코드를 읽으면
목록의 0부터 세는 세 번째 인덱스인 2025를 초기 선택으로 표시합니다.
프로젝트에서 쓰는 이유
선택한 year와 track으로 해당 profile을 찾습니다.
헷갈리기 쉬운 점
index=3은 3학년이나 2023이라는 뜻이 아닙니다. 목록의 네 번째 원소 위치입니다.
st.file_uploader()와 getvalue()

파일 선택 화면을 만들고 업로드 파일 객체를 반환합니다. 복수 모드면 파일 객체 목록을 반환합니다.

photos = st.file_uploader(
    "성적표", type=["jpg", "png"],
    accept_multiple_files=True,
)
for photo in photos:
    lines, boxes = recognize(photo.getvalue())
이 코드를 읽으면
각 photo의 실제 내용을 getvalue()로 바이트로 읽어 recognize에 전달합니다.
프로젝트에서 쓰는 이유
사진 파일을 OCR 코드와 연결합니다.
헷갈리기 쉬운 점
파일 이름을 읽는 것과 내용을 읽는 것은 다릅니다. 현재 코드는 업로드 사진을 별도 파일로 영구 저장하지 않습니다.
st.button()과 if

버튼이 클릭된 실행에서 True가 되어 해당 if 블록을 수행하게 합니다.

if st.button("졸업요건 사전 점검", disabled=not consent):
    result = audit(payload, profile)
이 코드를 읽으면
전체 검토 확인이 없으면 버튼을 비활성화합니다. 클릭하면 audit를 호출합니다.
프로젝트에서 쓰는 이유
OCR 실행·텍스트 가져오기·계산을 사용자가 시작하게 합니다.
헷갈리기 쉬운 점
버튼이 Python 코드를 계속 반복 실행하는 스위치는 아닙니다. 결과를 다음 재실행에도 유지하려고 session_state에 저장합니다.
st.session_state는 화면 상태를 보관합니다

현재 사용 세션 안에서 값을 저장하고, 화면 조작으로 스크립트가 재실행되어도 값을 유지하는 저장 공간입니다.

st.session_state["rows"] = rows
st.session_state["version"] += 1
st.session_state.pop("result", None)
이 코드를 읽으면
이수 내역을 저장하고 편집기 버전을 올린 뒤 이전 계산 결과를 제거합니다.
프로젝트에서 쓰는 이유
선택·수정·계산 결과가 화면 재실행마다 사라지지 않게 합니다.
헷갈리기 쉬운 점
영구 DB나 파일 저장 기능이 아닙니다. 세션이 끊기거나 앱을 다시 시작하면 유지되지 않을 수 있습니다. 여러 사용자에게 공용으로 영구 저장되는 변수도 아닙니다.
st.data_editor()와 CheckBoxColumn

표를 수정할 수 있는 UI를 만들고 편집 결과를 반환합니다. column_config는 열마다 입력 방식을 정합니다.

edited = st.data_editor(
    frame, num_rows="dynamic",
    column_config={
        "확인": st.column_config.CheckboxColumn(default=False)
    },
)
이 코드를 읽으면
사용자가 표에 행을 추가하거나 각 행의 확인 칸을 체크할 수 있습니다.
프로젝트에서 쓰는 이유
과목명·학점·성적의 OCR 오독을 사람이 보완합니다.
헷갈리기 쉬운 점
표의 체크박스는 각 과목별 확인입니다. 화면의 전체 검토 확인 st.checkbox와 같은 역할로 중복한 것이 아닙니다.
pd와 DataFrame은 무엇인가요?

pd는 pandas의 별명이고 DataFrame은 행과 열을 가진 표 자료구조입니다. 화면 자체가 아니라 데이터 구조입니다.

import pandas as pd
frame = pd.DataFrame(rows)
payload = frame.to_dict("records")
이 코드를 읽으면
행 목록을 표로 바꾸고, 다시 행 딕셔너리 목록으로 변환합니다.
프로젝트에서 쓰는 이유
편집기와 audit 함수 사이에서 데이터 형태를 맞춥니다.
헷갈리기 쉬운 점
st.dataframe은 읽기용 표 표시 함수입니다. pd.DataFrame과 이름이 비슷하지만 역할이 다릅니다. to_dict("records")는 파일 저장이 아니라 메모리 자료 변환입니다.
def는 함수를 정의합니다

이름 붙인 작업 묶음을 만드는 문법입니다. 괄호 안은 매개변수이고 들여쓴 본문은 호출할 때 실행됩니다.

def normalize(value):
    return str(value).strip().casefold()

name = normalize(" JAVA ")
이 코드를 읽으면
value라는 입력을 받아 정리한 문자열을 돌려주는 함수를 만들고 호출합니다.
프로젝트에서 쓰는 이유
OCR·파싱·학점 비교를 역할별로 나눕니다.
헷갈리기 쉬운 점
위 예시는 함수 문법을 보여주는 축약 예제입니다. 실제 normalize는 유니코드 정규화와 모든 공백 제거도 수행합니다.
return과 반환값

현재 함수 실행을 끝내고 호출한 쪽으로 값을 전달합니다. return이 없거나 값 없는 return은 None을 반환합니다.

def pair():
    return "JAVA", 3

name, credits = pair()
이 코드를 읽으면
두 값을 튜플로 묶어 반환하고 이름과 학점 변수로 나눠 받습니다.
프로젝트에서 쓰는 이유
recognize는 (lines, boxes), suggest는 (course, exact)를 반환합니다.
헷갈리기 쉬운 점
return은 화면 출력이나 파일 저장이 아닙니다. 반환한 결과를 st.write나 다른 코드가 사용해야 표시됩니다.
리스트·딕셔너리·튜플

리스트는 순서 있는 여러 값, 딕셔너리는 키와 값의 대응, 튜플은 묶음 표현에 사용합니다.

rows = [{"과목명": "JAVA", "학점": 3}]
name = rows[0]["과목명"]
position = (1, 2)
이 코드를 읽으면
첫 번째 행 딕셔너리에서 과목명 키에 해당하는 JAVA를 읽습니다.
프로젝트에서 쓰는 이유
여러 과목은 rows, 과목의 필드는 dict, 학년·학기 조합은 tuple로 표현합니다.
헷갈리기 쉬운 점
목록 인덱스는 0부터 시작합니다. dict에서 없는 키를 []로 읽으면 KeyError가 발생합니다.
dict.get()과 기본값

딕셔너리에서 키의 값을 읽고, 키가 없으면 지정한 기본값을 반환합니다.

category = row.get("이수구분", "미분류")
confirmed = row.get("확인")
이 코드를 읽으면
이수구분 키가 없으면 미분류, 확인 키가 없으면 기본 None을 받습니다.
프로젝트에서 쓰는 이유
누락된 입력 필드 때문에 곧바로 예외가 나는 일을 줄입니다.
헷갈리기 쉬운 점
키는 있는데 값이 None이나 빈칸인 경우 기본값으로 자동 대체하지는 않습니다. get은 키가 없는 경우를 처리합니다.
for와 enumerate()

목록 등의 항목을 차례로 처리합니다. enumerate는 항목과 함께 순서 번호도 줍니다.

for i, row in enumerate(rows, 1):
    name = row.get("과목명", "")
이 코드를 읽으면
첫 행은 i=1로 시작하고, 각 row를 하나씩 검사합니다.
프로젝트에서 쓰는 이유
성적표의 모든 과목을 같은 규칙으로 점검합니다.
헷갈리기 쉬운 점
enumerate(rows,1)의 1은 사용자에게 보여줄 행 번호 시작값입니다. 원래 리스트의 인덱스 체계를 바꾸는 것은 아닙니다.
if·elif·else와 논리 연산

조건에 따라 실행 경로를 나눕니다. and는 둘 다 참, or는 하나라도 참, not은 반대입니다.

if not consent or edited.empty:
    message = "검토 또는 입력이 필요합니다"
else:
    message = "점검할 수 있습니다"
이 코드를 읽으면
검토가 안 됐거나 표가 비었으면 점검할 수 없다는 경로를 고릅니다.
프로젝트에서 쓰는 이유
버튼 활성화, 오류 처리, 최종 상태를 결정합니다.
헷갈리기 쉬운 점
or 기본값 표현과 논리 비교는 같은 연산자의 서로 다른 활용입니다. 현재 코드는 최종 상태에 중첩 조건식을 사용하지만 같은 분기 원리입니다.
continue와 break

continue는 현재 항목의 나머지 처리를 건너뛰고 다음 반복으로 갑니다. break는 반복 전체를 끝냅니다.

for row in rows:
    if row.get("확인") is not True:
        continue
    # 확인한 행에 대해서만 뒤의 계산 수행
이 코드를 읽으면
확인하지 않은 과목 하나 때문에 전체 프로그램이 끝나지 않습니다.
프로젝트에서 쓰는 이유
audit의 부적합 행 건너뛰기와 PDF 합계 행에서 반복 종료에 사용합니다.
헷갈리기 쉬운 점
continue는 지금까지의 누적값을 초기화하지 않습니다. break와 return은 실행 종료 범위가 서로 다릅니다.
try·except와 raise

오류 가능 작업을 시도하고 지정한 예외를 처리합니다. raise는 오류를 직접 발생시킵니다.

try:
    credits = float(row.get("학점"))
except (ValueError, TypeError):
    credits = float("nan")
이 코드를 읽으면
학점을 숫자로 바꿀 수 없으면 NaN을 넣고 뒤의 유효성 검사에서 검토 대상으로 처리합니다.
프로젝트에서 쓰는 이유
잘못 입력한 학점이나 이미지 오류를 사용자 안내로 연결합니다.
헷갈리기 쉬운 점
예외를 잡았다고 오류가 해결된 것은 아닙니다. 이 코드에서는 문제 사유를 기록하고 정상 학점으로 합산하지 않습니다.
None과 is None

None은 값이 없음 또는 결과가 없음을 나타내는 Python 값입니다. 문자열 "None"과 다릅니다.

target = next((g for g in groups if matches(g)), None)
if target is None:
    groups.append([item])
이 코드를 읽으면
조건에 맞는 기존 행 그룹이 없으면 새 그룹을 만든다는 설명용 예제입니다.
프로젝트에서 쓰는 이유
유사 후보 없음, 매칭 그룹 없음, 심화 기준 없음 등을 표현합니다.
헷갈리기 쉬운 점
matches는 이 문법을 설명하기 위한 가상의 함수입니다. 실제 그룹 비교는 세로 좌표 차이 조건식으로 작성되어 있습니다.
append()와 extend()

리스트에 한 항목을 넣을 때 append, 다른 목록의 항목들을 각각 이어 붙일 때 extend를 사용합니다.

rows.append({"과목명": "JAVA", "학점": 3})
all_rows.extend(rows)
이 코드를 읽으면
한 행 딕셔너리를 추가하고, 여러 행을 전체 목록에 합칩니다.
프로젝트에서 쓰는 이유
OCR 여러 사진의 행을 모으고 issues·excluded에 사유를 쌓습니다.
헷갈리기 쉬운 점
append(rows)는 rows 목록 자체를 한 항목으로 넣어 중첩 목록을 만듭니다. extend(rows)와 다릅니다.
컴프리헨션은 반복하며 목록을 만듭니다

for와 조건을 한 표현식에 넣어 목록이나 딕셔너리를 만드는 문법입니다.

missing = [
    name for name in mandatory
    if normalize(name) not in accepted
]
이 코드를 읽으면
지정 의무 과목 중 인정 목록에 없는 이름만 모읍니다.
프로젝트에서 쓰는 이유
검색 인덱스·부족 항목·미이수 목록을 구성합니다.
헷갈리기 쉬운 점
짧게 쓰는 문법일 뿐 새로운 AI 기능이 아닙니다. 발표에서는 일반 for 반복으로 풀어서 설명해도 같은 처리 의미를 전달할 수 있습니다.
lambda와 sorted(key=...)

lambda는 간단한 함수를 식으로 작성합니다. sorted의 key에는 각 항목에서 비교 기준을 뽑는 함수를 줍니다.

ordered = sorted(boxes, key=lambda box: box["y"])
이 코드를 읽으면
각 box의 y값을 기준으로 위에서 아래로 정렬합니다.
프로젝트에서 쓰는 이유
OCR의 행 순서와 행 안의 글자 순서를 정합니다.
헷갈리기 쉬운 점
sorted는 정렬된 새 목록을 반환합니다. lambda box: box["x"]는 x 기준이며 y와 서로 다른 단계입니다.
언패킹과 _ 변수

묶인 값을 여러 변수로 나눠 받습니다. 필요 없는 반환값을 _에 넣는 것은 관례입니다.

lines, _ = recognize(photo.getvalue())
course, exact = suggest(name, profile)
이 코드를 읽으면
행 목록만 사용하고 영역 정보는 쓰지 않습니다. 과목 후보와 정확히 일치 여부는 둘 다 사용합니다.
프로젝트에서 쓰는 이유
반환값이 둘인 자체 함수를 연결합니다.
헷갈리기 쉬운 점
_는 값을 삭제하는 특수 문법이 아니라 평범한 변수 이름입니다. 읽는 사람에게 의도적으로 쓰지 않는 값임을 알리는 관례입니다.
@lru_cache는 데코레이터입니다

함수 앞의 @ 표현은 함수의 동작을 다른 기능으로 감싸는 데코레이터 문법입니다.

@lru_cache(maxsize=1)
def get_reader():
    return easyocr.Reader(["ko", "en"], gpu=False)
이 코드를 읽으면
get_reader를 호출할 때 이미 계산한 결과가 있으면 재사용하도록 감쌉니다.
프로젝트에서 쓰는 이유
큰 OCR 모델을 매번 다시 로드하지 않게 합니다.
헷갈리기 쉬운 점
예시는 캐시 문법에 집중해 인자를 줄인 것입니다. 실제 함수는 모델 저장 경로와 CUDA 가능 여부도 지정합니다.
float()와 math.isfinite()

float는 숫자로 변환하고, isfinite는 NaN이나 무한대가 아닌 유한 값인지 검사합니다.

credits = float("3")
valid = math.isfinite(credits) and 0 < credits <= 30
이 코드를 읽으면
"3"을 3.0으로 바꾸고 허용 범위의 숫자인지 확인합니다.
프로젝트에서 쓰는 이유
CSV나 편집기에서 들어온 학점이 계산 가능한지 점검합니다.
헷갈리기 쉬운 점
30은 과목당 프로그램 입력 상한입니다. 대학의 학기별 최대 수강학점을 의미하지 않습니다.
f-string과 표시 형식

문자열 앞에 f를 붙이고 중괄호 안의 값을 문장에 넣습니다.

message = f"{i}행 {name}: 원문 확인이 필요합니다."
label = f"{credits:g}학점"
이 코드를 읽으면
행 번호와 과목명을 안내에 넣습니다. :g는 3.0 같은 값을 간결하게 3으로 표시할 수 있습니다.
프로젝트에서 쓰는 이유
사용자가 어느 행을 수정해야 하는지 구체적으로 안내합니다.
헷갈리기 쉬운 점
f-string은 화면 표시를 위한 문자열 구성입니다. 파일 저장이나 학점 판정을 자동 수행하지 않습니다.
반환 딕셔너리와 대괄호 접근

audit가 반환한 여러 결과를 키로 구분해 꺼냅니다.

result = audit(payload, profile)
st.info(result["status"])
st.dataframe(pd.DataFrame(result["checks"]))
이 코드를 읽으면
status는 결과 문구, checks는 영역별 필요·인정·부족 학점 목록입니다.
프로젝트에서 쓰는 이유
계산 모듈의 결과를 화면 요소로 연결합니다.
헷갈리기 쉬운 점
result의 자료구조와 키 이름이 바뀌면 화면 코드도 함께 맞춰야 합니다. 코드 연결은 이 약속에 의존합니다.
json.loads()와 json.dumps()

JSON 문자열을 Python 값으로 읽거나 Python 값을 JSON 문자열로 만듭니다.

data = json.loads(path.read_text(encoding="utf-8"))
text = json.dumps(result, ensure_ascii=False, indent=2)
이 코드를 읽으면
파일에서 기준 데이터를 읽고 보고서를 한글이 보이는 문자열로 바꿉니다.
프로젝트에서 쓰는 이유
교육과정 저장 형식과 결과 다운로드에 사용합니다.
헷갈리기 쉬운 점
JSON은 데이터 표현 형식이며 Python 코드를 실행하는 기능이 아닙니다. 원본의 자료형과 필드 규칙은 별도 검사해야 합니다.
해시와 signature

입력의 내용을 고정 길이 식별 문자열로 요약해, 이전 계산과 현재 입력이 같은지 비교합니다.

signature = hashlib.sha256(
    json.dumps(payload, ensure_ascii=False).encode()
).hexdigest()
이 코드를 읽으면
표 데이터를 문자열·바이트로 바꾸고 SHA-256 식별값을 얻는 축약 예제입니다.
프로젝트에서 쓰는 이유
입력을 수정했을 때 오래된 결과를 표시하지 않게 합니다.
헷갈리기 쉬운 점
실제 signature에는 교육과정·의무 과목·옵션·검토 상태도 들어갑니다. 암호화·로그인·전자서명을 구현한 것이 아닙니다.
Path·__file__·parents

현재 소스 파일 위치를 기준으로 프로젝트 파일 경로를 구성합니다.

ROOT = Path(__file__).resolve().parents[1]
path = ROOT / "data" / "curriculum.json"
이 코드를 읽으면
상위 폴더로 이동한 경로에 data/curriculum.json을 연결합니다.
프로젝트에서 쓰는 이유
바탕화면처럼 폴더를 옮겨도 상대 구조가 같으면 필요한 파일을 찾게 합니다.
헷갈리기 쉬운 점
app.py는 파일이 프로젝트 바로 아래에 있어 .parent를 사용하고, graduation/ocr.py는 한 단계 더 안쪽이라 .parents[1]을 사용합니다.
정규표현식과 groups()

정해진 문자 패턴에 맞는 부분을 찾습니다. 괄호로 캡처한 값은 groups()로 나누어 받습니다.

m = re.match(r"^(.+?)\s+(\d+)\s+([A-Z][+0-]?)$", text)
if m:
    name, credits, grade = m.groups()
이 코드를 읽으면
"JAVA 3 B0"를 과목명·학점·성적 세 부분으로 분리하는 축약 예제입니다.
프로젝트에서 쓰는 이유
OCR의 단순 문자열을 계산 가능한 구조로 바꿉니다.
헷갈리기 쉬운 점
실제 패턴은 소수 학점·생략된 성적·일부 한글 상태를 더 지원합니다. 모든 학교 표 형식을 해석하는 범용 파서는 아닙니다.
이미지는 배열로 바꿔 모델에 전달합니다

Pillow가 이미지를 열고 NumPy가 픽셀 값을 배열로 바꿉니다. EasyOCR이 이 배열을 읽습니다.

image = Image.open(io.BytesIO(image_bytes)).convert("RGB")
detections = get_reader().readtext(np.array(image), detail=1)
이 코드를 읽으면
바이트 → 이미지 객체 → 숫자 배열 → OCR 결과 순서입니다.
프로젝트에서 쓰는 이유
서로 다른 라이브러리가 받을 수 있는 입력 자료형을 맞춥니다.
헷갈리기 쉬운 점
사진 속 글자를 문자열로 바꾸는 단계는 readtext입니다. np.array만 실행해서 문자가 인식되지는 않습니다.
sum()·max()와 +=

sum은 여러 수를 합하고 max는 가장 큰 값을 반환합니다. +=는 현재 값에 더한 뒤 저장합니다.

totals[category] += credits
missing = max(0, required - earned)
이 코드를 읽으면
영역별 학점을 쌓고 기준보다 적은 만큼만 부족으로 표시합니다.
프로젝트에서 쓰는 이유
과목 누적과 부족 학점 계산에 사용합니다.
헷갈리기 쉬운 점
교양합계·전공합계는 하위 항목을 묶은 값입니다. 부족 학점 항목들을 무조건 모두 더하면 중복 계산이 될 수 있습니다.
class·self와 테스트 메서드

class는 상태와 동작을 묶는 타입을 정의합니다. self는 해당 객체를 가리키는 첫 매개변수 관례입니다.

class AuditTests(unittest.TestCase):
    def test_example(self):
        self.assertEqual(3 + 3, 6)
이 코드를 읽으면
unittest의 검사 기능을 상속받고 하나의 테스트 메서드를 정의하는 예제입니다.
프로젝트에서 쓰는 이유
test_engine.py와 test_app.py에서 각 동작이 기대 결과와 같은지 확인합니다.
헷갈리기 쉬운 점
테스트 13개가 있다는 것은 특정 사례 13개를 검사한다는 뜻이지 OCR 정확도 100%를 증명하는 것은 아닙니다.
__name__ == "__main__"

파일을 직접 실행했을 때만 아래 코드를 실행하도록 구분하는 관례입니다.

if __name__ == "__main__":
    get_reader()
이 코드를 읽으면
모듈을 import할 때는 모델 준비 작업을 자동 시작하지 않고 직접 실행할 때만 시작합니다.
프로젝트에서 쓰는 이유
모델 준비·PDF 가져오기·실제 추론 시험 도구의 진입점을 구분합니다.
헷갈리기 쉬운 점
import 시 파일의 모든 코드가 실행되지 않는다는 뜻은 아닙니다. 함수 정의와 조건문 밖의 최상위 코드는 import 과정에서도 처리됩니다.
결과 표시용 Streamlit 함수

st.info·warning·error·success는 안내, st.dataframe은 표, metric은 지표를 표시합니다.

st.info(result["status"])
st.warning("최종 졸업 사정은 학과 확인이 필요합니다")
이 코드를 읽으면
결과의 의미와 주의사항을 화면에 보여줍니다.
프로젝트에서 쓰는 이유
숫자 결과뿐 아니라 검토할 사유와 적용 한계를 전달합니다.
헷갈리기 쉬운 점
안내 상자를 표시하는 함수가 졸업 기준 자체를 바꾸는 것은 아닙니다.
st.download_button()

메모리에 있는 문자열·바이트 등을 사용자가 내려받을 파일로 제공합니다.

st.download_button(
    "보고서 저장",
    json.dumps(result, ensure_ascii=False),
    file_name="graduation-check.json",
)
이 코드를 읽으면
결과를 JSON 문자열로 만들어 저장 버튼에 연결합니다.
프로젝트에서 쓰는 이유
결과를 파일로 받아 발표나 상담 자료로 사용할 수 있게 합니다.
헷갈리기 쉬운 점
서버의 임의 폴더에 자동 저장하는 함수가 아닙니다. 다운로드 위치는 사용자 브라우저 설정을 따릅니다.
st.tabs()와 with 탭 객체

탭 컨테이너 목록을 만들고 with로 각 컨테이너에 표시할 내용을 정합니다.

input_tab, rules_tab = st.tabs(["성적표 분석", "기준"])
with rules_tab:
    st.write(profile["minimums"])
이 코드를 읽으면
두 탭 객체를 나눠 받고 기준 탭에 최소학점을 표시합니다.
프로젝트에서 쓰는 이유
입력 화면과 교육과정 근거 화면을 나눕니다.
헷갈리기 쉬운 점
탭을 만든다고 각 탭의 Python 코드가 필요할 때만 실행되는 별도 프로그램이 되는 것은 아닙니다. 이 앱은 재실행 때 탭 내용도 구성합니다.
