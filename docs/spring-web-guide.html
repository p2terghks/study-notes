STEP 01

웹의 전체 구조

사용자가 저장 버튼을 누르면 다음 순서로 진행됩니다.

text
화면         요청 접수        작업 처리        DB 접근        저장
HTML    →    Controller   →   Service    →   Repository  →  DB
                                                │
                                        JPA / Hibernate 사용
이름 역할 예시
HTML 사용자가 보는 화면 입력창, 저장 버튼
Controller 요청을 받음 “할 일을 저장해 주세요”
Service 작업을 수행함 새 할 일을 미완료 상태로 생성
Repository DB에 접근함 저장, 조회, 삭제
Entity 저장할 데이터의 모양 번호, 제목, 완료 여부
DB 데이터를 보관함 저장된 할 일 목록

JPA와 DB는 다릅니다.

  • DB: 데이터를 저장하는 프로그램입니다. 여기서는 H2를 사용합니다.
  • JPA: Java 객체와 DB를 연결하는 표준입니다.
  • Hibernate: JPA를 구현해 SQL을 생성하고 DB에 전달합니다.
  • Spring Data JPA: Repository를 간단하게 작성하도록 돕습니다.

DB 연결하기

배울 것: 서버가 어느 DB에 접속할지 설정합니다.

파일: application.properties

properties
spring.datasource.url=jdbc:h2:file:./data/todos
spring.datasource.username=sa
spring.datasource.password=
spring.jpa.hibernate.ddl-auto=update
설정 의미

확인할 것: 같은 폴더에서 서버를 다시 실행하면 저장한 할 일이 남아 있습니다.

update는 학습용 설정입니다. 운영 DB의 구조 변경에는 별도의 마이그레이션 도구를 사용합니다.

STEP 04

Entity 만들기 — 무엇을 저장할까?

배울 것: 할 일 한 개가 가진 값을 정의합니다.

파일: Todo.java

java
@Entity
public class Todo {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String title;

    @Column(nullable = false)
    private boolean completed;

    // 생성자와 메서드는 실제 파일에 있습니다.
}
코드 쉽게 이해하기
@Entity “이 클래스를 DB에 저장할 대상으로 사용해 주세요.”
@Id 각 할 일을 구별하는 번호입니다.
@GeneratedValue DB가 번호를 자동으로 생성합니다.
@Column DB 열의 제약을 설정합니다.
String title 제목을 담습니다.
boolean completed 완료 여부를 true 또는 false로 담습니다.

DB에서는 다음과 같은 행으로 저장됩니다.

ID TITLE COMPLETED
1 스프링 공부하기 false
2 예제 실행하기 true

기억할 것: Todo 객체 한 개가 테이블의 한 행에 대응합니다.

STEP 05

Repository 만들기 — 어떻게 저장할까?

배울 것: Java 코드에서 DB를 읽고 쓰는 창구를 만듭니다.

파일: TodoRepository.java

java
public interface TodoRepository extends JpaRepository<Todo, Long> {
}

<Todo, Long>은 다음 뜻입니다.

  • Todo: 관리할 데이터의 종류
  • Long: ID의 자료형

이 선언만으로 기본 기능을 사용할 수 있습니다. 구현체는 Spring Data JPA가 만듭니다.

java
repository.save(new Todo("공부하기")); // 새 할 일 저장
repository.findAll();                // 전체 조회
repository.findById(1L);              // 1번 조회
repository.delete(todo);             // 해당 할 일 삭제

기억할 것: 기본 CRUD는 SQL을 직접 작성하지 않아도 됩니다.

STEP 06

Service 만들기 — 작업을 처리하는 곳

배울 것: 하나의 작업을 메서드로 묶습니다.

파일: TodoService.java

java
@Service
@Transactional(readOnly = true)
public class TodoService {
    private final TodoRepository todoRepository;

    public TodoService(TodoRepository todoRepository) {
        this.todoRepository = todoRepository;
    }

    @Transactional
    public void create(TodoForm form) {
        todoRepository.save(new Todo(form.getTitle().strip()));
    }
}
  1. @Service: 스프링이 이 객체를 만들어 관리합니다.
  2. 생성자: 스프링이 Repository를 전달합니다. 이를 의존성 주입이라고 합니다.
  3. @Transactional: 저장 작업에 트랜잭션을 적용합니다.
  4. strip(): 제목 앞뒤의 공백을 제거합니다.
  5. save(): 새 할 일을 저장합니다.

트랜잭션은 DB 작업을 하나로 묶는 단위입니다. 작업이 실패하면 변경을 되돌릴 수 있습니다. 기본적으로 RuntimeException이 밖으로 전파될 때 롤백합니다.

STEP 07

Controller 만들기 — 주소와 코드 연결

배울 것: 어떤 요청에 어떤 메서드가 실행될지 정합니다.

파일: TodoController.java

먼저 목록 조회 코드입니다.

java
@GetMapping("/todos")
public String list(Model model) {
    model.addAttribute("todos", todoService.findAll());
    return "todos/list";
}
순서 코드 역할
1 @GetMapping("/todos") GET /todos 요청을 받음
2 todoService.findAll() 할 일 목록 조회
3 model.addAttribute(...) 화면에 목록 전달
4 return "todos/list" 목록 HTML 선택

이 메서드는 @Controller가 붙은 클래스 안에 있습니다.

헷갈리지 않기
@Controller: HTML 화면을 보여줄 때 사용합니다.
@RestController: JSON 같은 데이터를 응답 본문으로 보낼 때 사용합니다.

STEP 08

HTML 입력과 검증 연결하기

배울 것: 입력창 → Java 객체 → 저장으로 이어지는 흐름입니다.

① 화면에서 제목 보내기

파일: new.html

html
<form th:action="@{/todos}" th:object="${todoForm}" method="post">
    <input type="text" th:field="*{title}" required maxlength="100">
    <button type="submit">저장</button>
</form>
  • th:action: 보낼 주소는 /todos입니다.
  • method="post": 저장 요청을 POST로 보냅니다.
  • th:field="*{title}": 입력값을 title이라는 이름으로 전달합니다.

② 입력받을 객체와 규칙 정의하기

파일: TodoForm.java

java
@NotBlank(message = "할 일을 입력해 주세요.")
@Size(max = 100, message = "할 일은 100자 이내로 입력해 주세요.")
private String title;
  • @NotBlank: 빈 값이나 공백뿐인 값을 거부합니다.
  • @Size: 길이를 제한합니다.

③ 컨트롤러에서 검사하고 저장하기

java
@PostMapping("/todos")
public String create(@Valid @ModelAttribute("todoForm") TodoForm form,
                     BindingResult bindingResult) {
    if (bindingResult.hasErrors()) {
        return "todos/new";
    }
    todoService.create(form);
    return "redirect:/todos";
}
코드 역할
@ModelAttribute 화면 입력을 TodoForm에 담음
@Valid 입력 검증 실행
BindingResult 검증 오류 보관. 검증 대상 바로 다음에 선언
hasErrors() 오류가 있으면 입력 화면을 다시 보여줌
create(form) 정상 입력이면 저장
redirect:/todos 저장 후 목록 주소로 이동

기억할 것: 브라우저 검사는 우회할 수 있어 서버에서도 검사합니다.

STEP 09

수정과 삭제하기

배울 것: ID로 기존 데이터를 찾아 변경합니다.

수정

서비스의 실제 수정 코드입니다.

java
@Transactional
public void update(Long id, TodoForm form) {
    Todo todo = findById(id);
    todo.update(form.getTitle().strip(), form.isCompleted());
}
  1. ID로 기존 할 일을 찾습니다.
  2. 제목과 완료 여부를 바꿉니다.
  3. 트랜잭션을 마칠 때 변경 내용이 DB에 반영됩니다.

왜 save()가 없을까요? 트랜잭션 안에서 조회한 엔티티를 JPA가 관리하고 있어 변경을 감지하기 때문입니다. 이를 변경 감지라고 합니다.

삭제

java
@Transactional
public void delete(Long id) {
    todoRepository.delete(findById(id));
}

ID로 할 일을 찾은 다음 삭제합니다. 존재하지 않는 ID는 예외로 처리해 404 응답을 보냅니다.

주소 정리

작업 HTTP 요청
목록 조회 GET /todos
등록 화면 GET /todos/new
등록 처리 POST /todos
수정 화면 GET /todos/{id}/edit
수정 처리 POST /todos/{id}/edit
삭제 처리 POST /todos/{id}/delete

기본 HTML 폼은 GET과 POST를 지원하므로 이 예제의 수정·삭제도 POST로 처리합니다.

전체 코드와 상세 설명

궁금한 항목을 펼쳐 보세요. import와 생성자 등을 포함한 전체 코드를 확인할 수 있습니다.

1. 웹은 어떻게 움직일까요?

브라우저는 화면을 보여주고 사용자의 입력을 받습니다. 서버는 요청을 받아 처리하고 응답합니다. DB는 데이터를 저장합니다.

예를 들어 할 일 저장 버튼을 누르면 다음 일이 일어납니다.

text
브라우저: title=스프링 공부를 POST /todos로 보냄
   ↓
Controller: 입력을 TodoForm에 담고 검증
   ↓
Service: 새 할 일을 저장하는 작업 수행
   ↓
Repository: save(todo) 호출
   ↓
JPA 구현체(Hibernate): INSERT SQL 생성 및 JDBC로 전달
   ↓
H2 DB: 데이터 저장
   ↓
서버: /todos로 이동하라는 응답
   ↓
브라우저: GET /todos 요청 → 목록 HTML 표시

HTTP는 브라우저와 서버의 요청·응답 규칙입니다. URL은 요청할 주소입니다. HTML은 화면의 구조, CSS는 모양을 표현합니다. 이 예제는 서버가 HTML을 완성해 보내므로 JavaScript 없이도 작동합니다.

2. 웹에는 어떤 기능이 필요할까요?

모든 웹이 같은 기능을 요구하지는 않습니다. 게시판, 쇼핑몰, 일정 관리에서는 다음 기능을 자주 씁니다.

필요한 기능 할 일 예제에서의 모습 담당 코드
화면 표시 목록·등록·수정 화면 HTML + Thymeleaf
요청 처리 주소와 실행 메서드 연결 Controller
작업 규칙 신규 등록은 미완료 상태로 시작 Service + Entity
저장·조회 서버 재시작 후에도 할 일 유지 Repository + JPA + DB
입력 검증 공백 거부, 100자 제한 TodoForm + @Valid
오류 처리 없는 할 일은 404 예외 클래스 + 오류 화면
동작 확인 저장부터 삭제까지 검증 통합 테스트
로그인·권한 나의 할 일만 변경 다음 학습 단계

등록(Create), 조회(Read), 수정(Update), 삭제(Delete)를 묶어 CRUD라고 합니다. 이번 예제는 이 네 기능을 모두 구현합니다.

3. 먼저 알아둘 Java 문법
  • class: 객체의 설계도입니다. Todo는 할 일 한 개의 설계도입니다.
  • new Todo("공부"): 설계도로 실제 객체를 만듭니다.
  • 필드: 객체가 가진 값입니다. title, completed가 해당합니다.
  • 메서드: 객체가 수행하는 동작입니다. update(...)가 해당합니다.
  • 생성자: 객체가 만들어질 때 실행하는 코드입니다. 클래스 이름과 같습니다.
  • private: 클래스 바깥에서 필드를 직접 바꾸지 못하게 합니다.
  • getter/setter: 값을 읽고 쓰는 메서드입니다. 스프링의 폼 입력 연결과 템플릿에서도 사용합니다.
  • Long: 정수 값을 담는 타입이며 null도 가능합니다. 저장 전에는 id가 없습니다.
  • boolean: true 또는 false입니다.
  • List<Todo>: 여러 할 일을 담은 목록입니다.
  • interface: 제공할 동작의 규약입니다. Repository 구현은 Spring Data JPA가 맡습니다.
  • final: 해당 필드에 다른 객체를 다시 대입하지 못하게 합니다.
  • package/import: 클래스의 소속과 다른 클래스를 가져오는 선언입니다.
4. 프로젝트 구성과 의존성

pom.xml은 필요한 라이브러리와 빌드 설정을 선언합니다. Maven은 이 파일을 읽어 라이브러리를 내려받고 코드를 컴파일합니다. mvnw는 정해진 Maven을 실행하는 도우미입니다.

라이브러리 역할
spring-boot-starter-webmvc HTTP 요청, 컨트롤러, 내장 웹 서버
spring-boot-starter-thymeleaf HTML에 Java 데이터 연결
spring-boot-starter-data-jpa 객체를 통한 DB 접근
h2 별도 설치 없이 실행하는 DB
spring-boot-starter-validation 입력값 검증

6. DB 연결 설정하기

DB는 데이터를 저장하는 프로그램이고, 테이블은 행과 열로 데이터를 정리한 공간입니다. TODO 테이블에는 ID, TITLE, COMPLETED 열이 만들어집니다.

jdbc:h2:file:./data/todos는 H2 파일 DB의 주소입니다. jdbc는 Java의 DB 연결 방식을 가리키고, file은 디스크 저장 방식을 뜻합니다. 이 주소는 웹 브라우저 주소가 아닙니다.

파일: src/main/resources/application.properties

spring.datasource.password=

# 학습용 자동 테이블 생성/변경. 운영에서는 마이그레이션 도구를 사용합니다.

ddl-auto=update를 설정하면 Hibernate가 엔티티 정보를 보고 테이블 생성·변경을 시도합니다. 모든 스키마 변경을 안전하게 처리하는 기능은 아니므로 운영에서는 Flyway 같은 마이그레이션 도구를 사용합니다. create 또는 create-drop으로 바꾸면 기존 데이터가 사라질 수 있습니다.

show-sql=true로 DB에 실행되는 SQL을 서버 터미널에서 볼 수 있습니다. open-in-view=false는 화면 렌더링까지 JPA 영속성 컨텍스트를 계속 열어 두지 않도록 합니다. 지금은 단순 필드만 사용하므로 서비스가 반환한 값을 화면에서 바로 읽을 수 있습니다.

7. Entity: 저장할 데이터 정의하기

Todo 객체 한 개를 DB 테이블 한 행에 대응시킵니다. JPA는 Java 객체와 관계형 DB를 연결하는 표준이고, Hibernate는 그 표준을 실제로 구현합니다. Spring Data JPA는 그 위에서 Repository 작성량을 줄여 줍니다. DB 자체가 JPA인 것은 아닙니다.

파일: src/main/java/com/example/todolearning/todo/Todo.java

java
package com.example.todolearning.todo;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

// 자바 객체를 DB 테이블의 한 행과 연결합니다.
@Entity
public class Todo {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String title;

    @Column(nullable = false)
    private boolean completed;

    // JPA가 DB 데이터를 객체로 만들 때 사용하는 기본 생성자입니다.
    protected Todo() {
    }

    public Todo(String title) {
        this.title = title;
        this.completed = false;
    }

    public void update(String title, boolean completed) {
        this.title = title;
        this.completed = completed;
    }

    public Long getId() { return id; }
    public String getTitle() { return title; }
    public boolean isCompleted() { return completed; }
}
  • @Entity: 이 클래스를 JPA가 관리하는 엔티티로 등록합니다.
  • @Id: 각 행을 구분하는 기본 키입니다. 제목이 같아도 ID로 다른 할 일을 구별합니다.
  • @GeneratedValue: 기본 키 생성 방식을 정합니다. IDENTITY는 DB의 자동 증가 기능을 사용합니다.
  • @Column(nullable=false, length=100): 열의 제약을 정의합니다. length는 문자열 열에 적용합니다.
  • protected Todo(): JPA가 객체를 복원할 때 필요한 기본 생성자입니다.

@Column(nullable=false)는 공백 문자열을 막는 규칙은 아닙니다. 공백 입력은 다음 단계의 검증으로 막습니다.

새 객체는 completed=false로 만들어지며, 저장하면 DB가 ID를 생성합니다. 전 필드의 setter를 만드는 대신 update()로 변경 가능한 내용을 명시했습니다.

8. Form/DTO: 입력값 받기와 검증

폼에서 들어오는 값은 TodoForm으로 받습니다. DTO는 데이터를 옮기는 객체라는 뜻입니다. DB 엔티티를 그대로 입력 대상으로 쓰면 사용자가 바꾸면 안 되는 필드까지 입력받기 쉬워집니다.

파일: src/main/java/com/example/todolearning/todo/TodoForm.java

java
package com.example.todolearning.todo;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

// 화면 입력 전용 객체(DTO). DB 객체인 Todo와 역할을 구분합니다.
public class TodoForm {
    @NotBlank(message = "할 일을 입력해 주세요.")
    @Size(max = 100, message = "할 일은 100자 이내로 입력해 주세요.")
    private String title;

    private boolean completed;

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    public boolean isCompleted() { return completed; }
    public void setCompleted(boolean completed) { this.completed = completed; }
}

@NotBlank는 null, 빈 문자열, 공백뿐인 문자열을 거부합니다. @Size(max=100)은 문자열 길이를 제한합니다. 어노테이션을 붙이는 것만으로 아무 때나 검증되지는 않습니다. 뒤에서 컨트롤러의 @Valid가 검증을 요청합니다.

HTML의 required와 maxlength는 사용자 편의를 위한 브라우저 검사입니다. 직접 HTTP 요청을 보낼 수도 있으므로 서버에서도 검사해야 합니다.

9. Repository: DB 읽고 쓰기

파일: src/main/java/com/example/todolearning/todo/TodoRepository.java

java
package com.example.todolearning.todo;

import org.springframework.data.jpa.repository.JpaRepository;

// <관리할 엔티티, 기본 키 타입>. 구현체는 Spring Data JPA가 생성합니다.
public interface TodoRepository extends JpaRepository<Todo, Long> {
}

JpaRepository<Todo, Long>은 Todo 엔티티를 다루고 기본 키 타입은 Long이라는 뜻입니다. 일반 Java 인터페이스가 혼자 실행되는 것은 아닙니다. Spring Data JPA가 실행 시 구현체를 만들어 스프링에 등록합니다. 이 인터페이스에 @Repository를 추가하지 않아도 됩니다.

Java 호출 개념상 SQL 의미
save(new Todo("공부")) INSERT INTO todo ... 새 행 저장
findAll() SELECT ... FROM todo 전체 조회
findById(1L) SELECT ... WHERE id = ? ID로 조회
delete(todo) DELETE FROM todo WHERE id = ? 삭제

실제 SQL과 실행 시점은 엔티티 상태, 키 생성 방식, flush 시점 등에 따라 달라집니다. save()가 언제나 INSERT라는 뜻은 아닙니다. 위 표는 신규 객체 저장의 예입니다.

findById()는 Optional<Todo>를 반환합니다. 조회 결과가 없을 가능성을 표현하는 상자라고 생각하세요. 다음 서비스에서는 결과가 없으면 예외를 던집니다.

10. Service: 하나의 작업과 트랜잭션

파일: src/main/java/com/example/todolearning/todo/TodoService.java

java
package com.example.todolearning.todo;

import java.util.List;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@Transactional(readOnly = true)
public class TodoService {
    private final TodoRepository todoRepository;

    // 생성자 주입: 스프링이 필요한 Repository를 넣어 줍니다.
    public TodoService(TodoRepository todoRepository) {
        this.todoRepository = todoRepository;
    }

    public List<Todo> findAll() {
        return todoRepository.findAll(Sort.by(Sort.Direction.DESC, "id"));
    }

    public Todo findById(Long id) {
        return todoRepository.findById(id)
                .orElseThrow(() -> new TodoNotFoundException(id));
    }

    @Transactional
    public void create(TodoForm form) {
        todoRepository.save(new Todo(form.getTitle().strip()));
    }

    @Transactional
    public void update(Long id, TodoForm form) {
        Todo todo = findById(id);
        todo.update(form.getTitle().strip(), form.isCompleted());
        // 트랜잭션 안에서 조회한 엔티티의 변경은 커밋 때 DB에 반영됩니다.
        // 이 동작을 변경 감지(dirty checking)라고 부릅니다.
    }

    @Transactional
    public void delete(Long id) {
        todoRepository.delete(findById(id));
    }
}

@Service를 붙이면 스프링이 이 객체를 생성해 관리합니다. 이렇게 관리되는 객체를 **빈(bean)**이라고 합니다.

생성자의 TodoRepository는 직접 new로 만들지 않습니다. 스프링이 이미 준비한 Repository를 전달합니다. 이를 **의존성 주입(DI)**이라고 합니다. 생성자가 하나이면 @Autowired를 생략할 수 있습니다.

트랜잭션은 여러 DB 변경을 하나의 작업으로 묶는 경계입니다. 예를 들어 계좌 이체에서는 출금만 되고 입금은 실패하는 상황을 막아야 합니다. 스프링의 기본 설정에서는 처리 중 RuntimeException이 밖으로 전파되면 롤백합니다. 모든 예외가 기본적으로 롤백되는 것은 아닙니다.

클래스의 @Transactional(readOnly=true)는 조회 중심의 기본 설정이고, 저장·수정·삭제 메서드의 @Transactional은 쓰기 작업 설정으로 덮어씁니다. readOnly는 최적화 힌트로, 접근 권한을 강제로 제한하는 보안 기능은 아닙니다.

수정 메서드에서는 save()를 다시 호출하지 않습니다. 트랜잭션 안에서 조회한 엔티티를 JPA가 관리하고 있어 값의 변화를 감지합니다. 커밋할 때 필요한 UPDATE가 반영됩니다. 아무 객체나 바꿨다고 저장되는 것은 아닙니다.

스프링 트랜잭션은 보통 프록시를 통해 적용됩니다. 이 예제는 컨트롤러가 서비스의 public 메서드를 호출하면서 경계가 시작됩니다. 같은 클래스 안의 메서드 호출만으로 새로운 트랜잭션 어노테이션이 적용되지는 않습니다.

11. 없는 데이터는 404로 처리하기

파일: src/main/java/com/example/todolearning/todo/TodoNotFoundException.java

java
package com.example.todolearning.todo;

import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ResponseStatus;

@ResponseStatus(HttpStatus.NOT_FOUND)
public class TodoNotFoundException extends RuntimeException {
    public TodoNotFoundException(Long id) {
        super("할 일을 찾을 수 없습니다: " + id);
    }
}

orElseThrow(() -> new TodoNotFoundException(id))는 조회 결과가 없을 때 실행합니다. () -> ...는 필요할 때 실행할 동작을 전달하는 람다 문법입니다.

@ResponseStatus(HttpStatus.NOT_FOUND)는 이 예외를 HTTP 404에 연결합니다. 200은 성공, 302는 다른 주소로 이동, 404는 대상 없음, 500은 서버 내부 오류를 나타냅니다.

12. Controller: 주소와 Java 메서드 연결하기

컨트롤러는 요청의 입구입니다. 입력을 받고, 서비스에 작업을 부탁하고, 어떤 화면을 보여줄지 결정합니다.

요청 목적
GET /todos 목록 조회
GET /todos/new 등록 화면
POST /todos 등록 처리
GET /todos/{id}/edit 수정 화면
POST /todos/{id}/edit 수정 처리
POST /todos/{id}/delete 삭제 처리

GET은 조회에 사용합니다. 데이터를 변경하는 요청은 GET으로 만들지 않습니다. 기본 HTML 폼은 GET과 POST를 지원하므로 여기서는 수정·삭제도 POST로 처리합니다. JSON REST API에서는 PUT/PATCH/DELETE를 흔히 사용합니다.

파일: src/main/java/com/example/todolearning/todo/TodoController.java

java
package com.example.todolearning.todo;

import jakarta.validation.Valid;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ModelAttribute;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;

@Controller
public class TodoController {
    private final TodoService todoService;

    public TodoController(TodoService todoService) {
        this.todoService = todoService;
    }

    @GetMapping("/")
    public String home() {
        return "redirect:/todos";
    }

    @GetMapping("/todos")
    public String list(Model model) {
        model.addAttribute("todos", todoService.findAll());
        return "todos/list";
    }

    @GetMapping("/todos/new")
    public String newForm(Model model) {
        model.addAttribute("todoForm", new TodoForm());
        return "todos/new";
    }

    @PostMapping("/todos")
    public String create(@Valid @ModelAttribute("todoForm") TodoForm form,
                         BindingResult bindingResult) {
        // BindingResult는 검증 대상 매개변수 바로 다음에 둡니다.
        if (bindingResult.hasErrors()) {
            return "todos/new";
        }
        todoService.create(form);
        return "redirect:/todos";
    }

    @GetMapping("/todos/{id}/edit")
    public String editForm(@PathVariable("id") Long id, Model model) {
        Todo todo = todoService.findById(id);
        TodoForm form = new TodoForm();
        form.setTitle(todo.getTitle());
        form.setCompleted(todo.isCompleted());
        model.addAttribute("todoForm", form);
        model.addAttribute("todoId", id);
        return "todos/edit";
    }

    @PostMapping("/todos/{id}/edit")
    public String update(@PathVariable("id") Long id,
                         @Valid @ModelAttribute("todoForm") TodoForm form,
                         BindingResult bindingResult, Model model) {
        if (bindingResult.hasErrors()) {
            model.addAttribute("todoId", id);
            return "todos/edit";
        }
        todoService.update(id, form);
        return "redirect:/todos";
    }

    @PostMapping("/todos/{id}/delete")
    public String delete(@PathVariable("id") Long id) {
        todoService.delete(id);
        return "redirect:/todos";
    }
}

목록 메서드를 먼저 읽어 보세요.

java
@GetMapping("/todos")
public String list(Model model) {
    model.addAttribute("todos", todoService.findAll());
    return "todos/list";
}
  1. 브라우저가 GET /todos를 요청하면 list()가 실행됩니다.
  2. 서비스에서 할 일 목록을 가져옵니다.
  3. Model이라는 화면용 데이터 보관함에 todos라는 이름으로 넣습니다.
  4. todos/list를 반환하면 Thymeleaf가 templates/todos/list.html을 렌더링합니다.

다음으로 등록 메서드를 읽어 보세요.

  • @ModelAttribute("todoForm"): 폼의 이름과 객체 필드를 연결하고 모델에도 제공합니다.
  • @Valid: TodoForm에 선언한 검증을 실행합니다.
  • BindingResult: 검증 오류를 담습니다. 반드시 해당 입력 매개변수 바로 뒤에 둡니다.
  • 오류가 있으면 등록 화면을 다시 보여줍니다. 입력값과 오류 정보가 유지됩니다.
  • 성공하면 redirect:/todos를 반환합니다. 브라우저가 새로운 GET 요청으로 목록을 엽니다.

이 흐름을 Post/Redirect/Get이라고 합니다. 성공한 POST 화면을 새로고침할 때 같은 등록 요청을 다시 보내는 일을 줄입니다. 빠른 중복 클릭까지 모두 방지하는 기능은 아닙니다.

@PathVariable("id")는 /todos/3/edit에서 숫자 3을 받습니다. @RequestParam은 /todos?keyword=공부의 검색 조건 같은 쿼리 매개변수를 받을 때 사용합니다. @RequestBody는 JSON 요청 본문을 객체로 받을 때 사용하며, 이 HTML 폼 예제에는 필요하지 않습니다.

@Controller의 문자열 반환은 주로 화면 이름입니다. @RestController는 @Controller와 @ResponseBody를 합친 것으로, 반환값을 응답 본문에 씁니다. 객체는 보통 JSON으로 변환되고 문자열은 그 문자열 자체가 전달됩니다. 따라서 이 코드의 어노테이션만 RestController로 바꾸면 화면 대신 todos/list라는 글자가 나옵니다.

13. HTML: 실제로 보고 누르는 화면

Thymeleaf는 서버의 데이터를 HTML에 넣는 템플릿 엔진입니다. Java 코드에서 넣은 todos를 ${todos}로 읽습니다.

목록 화면

파일: src/main/resources/templates/todos/list.html

html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head><meta charset="UTF-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>할 일 목록</title><link rel="stylesheet" th:href="@{/css/style.css}"></head>
<body><main>
    <p class="eyebrow">나의 첫 Spring 웹</p>
    <h1>할 일 목록</h1>
    <p>작은 할 일 하나부터 기록해 보세요.</p>
    <a class="button" th:href="@{/todos/new}">새 할 일 등록</a>
    <p th:if="${#lists.isEmpty(todos)}" class="empty">아직 할 일이 없습니다. 첫 할 일을 등록해 보세요.</p>
    <ul class="todos">
        <li th:each="todo : ${todos}">
            <div><span class="badge" th:text="${todo.completed ? '완료' : '진행 중'}"></span>
                <strong th:text="${todo.title}"></strong></div>
            <div class="actions">
                <a th:href="@{/todos/{id}/edit(id=${todo.id})}">수정</a>
                <form th:action="@{/todos/{id}/delete(id=${todo.id})}" method="post">
                    <button class="delete" type="submit">삭제</button>
                </form>
            </div>
        </li>
    </ul>
</main></body></html>
  • th:each: 목록만큼 반복합니다.
  • th:text: 텍스트를 출력하며 HTML 특수문자를 이스케이프합니다. 입력한 <script>가 코드로 실행되지 않게 합니다.
  • th:if: 조건이 맞을 때만 표시합니다.
  • th:href와 th:action: 링크와 폼 전송 주소를 만듭니다.
  • @{/todos/{id}/edit(id=${todo.id})}: 실제 ID가 들어간 주소를 생성합니다.

등록 화면

파일: src/main/resources/templates/todos/new.html

html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head><meta charset="UTF-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>할 일 등록</title><link rel="stylesheet" th:href="@{/css/style.css}"></head>
<body><main>
    <p class="eyebrow">CREATE · 등록</p><h1>새 할 일</h1>
    <form th:action="@{/todos}" th:object="${todoForm}" method="post">
        <label for="title">할 일</label>
        <input id="title" type="text" th:field="*{title}" maxlength="100" required placeholder="예: 컨트롤러 역할 이해하기" aria-describedby="title-error">
        <p id="title-error" class="error" th:if="${#fields.hasErrors('title')}" th:errors="*{title}"></p>
        <div class="actions"><button type="submit">저장</button><a th:href="@{/todos}">취소</a></div>
    </form>
</main></body></html>

th:object="${todoForm}"은 이 폼이 사용할 객체입니다. th:field="*{title}"은 해당 객체의 title과 입력을 연결하며 name, id, value 등을 생성합니다. 폼을 제출하면 title이라는 이름으로 입력값이 전송됩니다.

th:errors는 서버 검증 오류를 출력합니다. 이 예제는 검증 실패 시 HTML 화면을 200으로 다시 보여줍니다. 검증 오류를 반드시 400으로 응답해야 하는 것은 아닙니다. JSON API에서는 400과 오류 JSON을 흔히 사용합니다.

수정 화면

파일: src/main/resources/templates/todos/edit.html

html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head><meta charset="UTF-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>할 일 수정</title><link rel="stylesheet" th:href="@{/css/style.css}"></head>
<body><main>
    <p class="eyebrow">UPDATE · 수정</p><h1>할 일 수정</h1>
    <form th:action="@{/todos/{id}/edit(id=${todoId})}" th:object="${todoForm}" method="post">
        <label for="title">할 일</label>
        <input id="title" type="text" th:field="*{title}" maxlength="100" required aria-describedby="title-error">
        <p id="title-error" class="error" th:if="${#fields.hasErrors('title')}" th:errors="*{title}"></p>
        <label class="checkbox"><input type="checkbox" th:field="*{completed}"> 완료했어요</label>
        <div class="actions"><button type="submit">수정 저장</button><a th:href="@{/todos}">취소</a></div>
    </form>
</main></body></html>

수정 화면에서는 기존 값을 TodoForm에 복사해서 보여줍니다. Thymeleaf의 체크박스 필드 처리는 체크를 해제했을 때도 boolean 값이 적절히 전달되도록 돕습니다.

404 화면

파일: src/main/resources/templates/error/404.html

html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head><meta charset="UTF-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>찾을 수 없습니다</title><link rel="stylesheet" th:href="@{/css/style.css}"></head>
<body><main><p class="eyebrow">404</p><h1>요청한 내용을 찾을 수 없습니다.</h1><p>삭제된 할 일이거나 잘못된 주소일 수 있습니다.</p><a th:href="@{/todos}">목록으로 돌아가기</a></main></body></html>

Spring Boot의 기본 오류 처리에서 HTML 응답에 사용할 상태 코드별 화면입니다. 존재하지 않는 할 일뿐 아니라 없는 URL에도 사용할 수 있도록 문구를 작성했습니다.

CSS는 src/main/resources/static/css/style.css에 있습니다. static 아래 파일은 정적 리소스로 제공되어 브라우저가 /css/style.css로 가져옵니다.

14. 어노테이션 한눈에 보기

어노테이션은 @로 붙이는 메타데이터입니다. 표시만으로 마법처럼 모든 것이 실행되는 것은 아니고, 스프링·JPA·검증 라이브러리가 이를 읽고 동작을 적용합니다. Java의 @Override처럼 컴파일러가 확인하는 어노테이션도 있습니다.

어노테이션 읽는 쪽 역할
@SpringBootApplication Spring Boot 시작 설정, 자동 설정, 컴포넌트 탐색
@Controller Spring MVC 화면 요청 처리 빈
@Service Spring 서비스 빈 등록
@GetMapping / @PostMapping Spring MVC HTTP 메서드와 경로 연결
@PathVariable Spring MVC URL 경로 변수 연결
@ModelAttribute Spring MVC 폼 입력 연결, 모델 제공
@Valid 검증 연동 객체의 검증 규칙 실행 요청
@NotBlank / @Size Bean Validation 공백 및 길이 제약
@Transactional Spring 트랜잭션 작업의 트랜잭션 경계
@Entity JPA 영속 엔티티 선언
@Id / @GeneratedValue JPA 기본 키와 생성 방식
@Column JPA 열 매핑과 제약
@ResponseStatus Spring MVC 응답 상태 코드 지정

Entity가 자동으로 Service와 같은 스프링 빈이 되는 것은 아닙니다. 엔티티 인스턴스의 영속 상태는 JPA가 관리하고, Controller와 Service의 객체 생명주기는 스프링 컨테이너가 관리합니다.

15. 실행하며 DB와 연결해 보기

프로젝트 터미널에서 실행합니다.

sh
./mvnw spring-boot:run

http://localhost:8080/todos에서 등록·수정·삭제를 해 보세요. 동시에 터미널의 SQL을 보면 Java 메서드가 실제 DB 작업으로 이어지는 것을 확인할 수 있습니다.

http://localhost:8080/h2-console에 접속하고 JDBC URL을 jdbc:h2:file:./data/todos, 사용자명을 sa, 비밀번호를 빈 값으로 입력합니다.

sql
SELECT id, title, completed FROM todo ORDER BY id DESC;

목록의 한 항목이 DB의 한 행입니다. 수정 후 다시 SELECT를 실행해 title이나 completed가 바뀌었는지 확인하세요. 서버를 껐다 켜도 같은 실행 폴더를 사용하면 데이터가 남아 있습니다.

16. 테스트는 왜 필요할까요?

컴파일 성공은 문법과 타입 검사를 통과했다는 뜻입니다. 실제 요청이 올바른 테이블 변경으로 이어지는지까지 보장하지는 않습니다.

sh
./mvnw test

TodoWebIntegrationTests는 실제 임시 포트의 서버로 HTTP 요청을 보냅니다. 등록 → 조회 → 수정 → 완료 해제 → 삭제, 공백·길이 검증, 없는 ID, 출력 이스케이프를 검사합니다. 테스트 DB는 메모리 기반이어서 학습 중 저장한 파일 DB에 영향을 주지 않습니다.

17. 다음에는 무엇을 만들까요?

한 번에 전부 외우기보다 다음 순서로 확장해 보세요.

  1. 설명 필드 추가: Entity → Form → Service → HTML에 description 추가. 값이 어디를 지나가는지 익힙니다.
  2. 검색: Repository에 findByTitleContaining(String keyword)를 선언하고 Controller에서 @RequestParam으로 검색어를 받습니다. Spring Data가 메서드 이름을 해석합니다.
  3. 페이징: 모든 데이터를 한 번에 읽는 대신 Pageable과 Page로 나눕니다.
  4. JSON API: 별도의 RestController에서 DTO를 반환하고 화면과 서버를 분리해 봅니다.
  5. 로그인·권한: Spring Security로 사용자를 구분하고 본인의 할 일만 변경하도록 검증합니다. 비밀번호는 직접 평문 저장하지 않습니다.
  6. 운영 DB: MySQL/PostgreSQL 드라이버와 연결 설정, 환경변수, 마이그레이션을 익힙니다. DB를 바꾸면 SQL과 타입 차이도 확인해야 합니다.

현재 예제는 인증과 CSRF 보호를 포함하지 않는 로컬 학습용입니다. 사용자별 권한과 외부 공개 설정은 위 확장 단계에서 다룹니다.

  • Spring Boot: SQL 데이터베이스: DB 연결과 JPA 설정

  • Spring Data JPA: Repository 추상화
