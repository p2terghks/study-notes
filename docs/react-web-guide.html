STEP 01

React는 어디에 사용할까?

React는 버튼, 입력창, 목록 같은 웹 화면을 만드는 JavaScript 라이브러리입니다.

기술 담당 역할 할 일 웹에서의 예
React 브라우저 화면과 사용자 입력 제목 입력, 목록 표시
Spring 서버 요청 처리와 작업 규칙 입력 검증, 저장 처리
JPA / Hibernate 객체와 DB 연결 SQL 생성과 실행
DB 데이터 보관 할 일 제목과 완료 여부 저장
text
사용자 → React 화면 → HTTP / JSON → Spring → JPA → DB
             ↑                        │
             └──── 결과 데이터 ────────┘

기존 Spring 예제는 Thymeleaf가 서버에서 HTML을 만듭니다. 이번에 배우는 방식에서는 React가 브라우저에서 화면을 만들고 Spring API와 데이터를 주고받습니다.

이번 학습 범위 — 먼저 서버 없이 동작하는 할 일 예제를 이해합니다. Spring 연결 코드는 뒤에서 구조를 설명하는 예시로 다룹니다. 현재 Spring 프로젝트에 React나 JSON API가 추가된 것은 아닙니다.

STEP 02

시작 전에 알아둘 JavaScript

JSX를 읽기 위해 자주 쓰는 문법만 먼저 익힙니다.

js
const title = "리액트 공부";
const todo = { id: 1, title, completed: false };
const todos = [todo];

const { id, completed } = todo;
const titles = todos.map((item) => item.title);
const nextTodos = [...todos, { id: 2, title: "복습", completed: false }];
문법 의미
const 다른 값으로 재대입하지 않는 변수 선언
{ id: 1, title } 객체. title은 title: title의 축약
[todo] 항목들을 담는 배열
const { id } = todo 객체의 id를 꺼내는 구조 분해
(item) => item.title 입력을 받아 결과를 반환하는 화살표 함수
map() 각 항목을 변환한 새 배열 생성
...todos 기존 배열의 항목 펼치기

const는 객체 내부 값까지 불변으로 만드는 문법은 아닙니다. React 상태를 직접 바꾸지 않는 규칙은 별도로 지켜야 합니다.

STEP 03

Component — 화면을 함수로 만들기

컴포넌트는 화면을 구성하는 재사용 가능한 조각입니다.

jsx
function Welcome() {
  return <h1>할 일 관리</h1>;
}

export default function App() {
  return (
    <main>
      <Welcome />
      <p>오늘 할 일을 기록해 보세요.</p>
    </main>
  );
}
  1. Welcome()은 제목 화면을 반환합니다.
  2. App()은 화면 전체를 구성하는 컴포넌트입니다.
  3. <Welcome /> 위치에 제목이 표시됩니다.
  4. export default는 다른 파일에서 이 컴포넌트를 가져올 수 있게 합니다.
이름 첫 글자 React의 해석
<main> 소문자 브라우저 기본 HTML 요소
<Welcome /> 대문자 직접 만든 React 컴포넌트

컴포넌트 함수를 다른 컴포넌트 함수 안에 정의하지 말고 바깥에 정의하세요. 화면에서 사용할 때는 <Welcome />처럼 JSX로 씁니다.

STEP 04

JSX — JavaScript 안에 화면 쓰기

JSX는 HTML과 비슷한 화면 작성 문법입니다. JavaScript 값은 중괄호 안에 넣습니다.

jsx
function Greeting() {
  const name = "민수";

  return (
    <>
      <h1 className="title">{name}님, 안녕하세요!</h1>
      <p>오늘 할 일은 {2 + 1}개입니다.</p>
    </>
  );
}
코드 화면 또는 의미
{name} 민수
{2 + 1} 3
className HTML의 class에 해당
<>...</> 여러 요소를 묶는 Fragment. 별도 DOM 요소는 만들지 않음

JSX에서는 태그를 닫아야 합니다. 입력창은 <input />으로 씁니다. label의 for는 htmlFor로 씁니다.

JSX는 빌드 도구를 통해 JavaScript로 변환됩니다. 일반 HTML 파일에 JSX만 붙여 넣어서는 실행되지 않습니다. 공식 JSX 안내

STEP 05

Props — 부모에서 자식으로 값 전달

Props는 컴포넌트가 외부에서 전달받는 값입니다.

jsx
function TodoItem({ title, completed }) {
  return (
    <li>
      {title} · {completed ? "완료" : "진행 중"}
    </li>
  );
}

function App() {
  return (
    <ul>
      <TodoItem title="스프링 공부" completed={true} />
      <TodoItem title="리액트 공부" completed={false} />
    </ul>
  );
}
text
App (부모)
  └─ title, completed 전달 → TodoItem (자식)

{ title, completed }는 props 객체에서 두 값을 꺼내는 문법입니다. completed={false}는 boolean 값이고, completed="false"는 문자열이므로 다릅니다.

Props는 읽기 전용입니다. 자식이 값을 바꾸고 싶다면 부모가 전달한 함수를 호출해 변경을 요청합니다. 함수도 props로 전달할 수 있습니다. 공식 Props 안내

STEP 06

State — 기억하고 변경하는 값

State는 컴포넌트가 기억하는 값입니다. setter를 호출하면 다음 렌더링에 새 값이 반영됩니다.

jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount((previous) => previous + 1)}>
      클릭 횟수: {count}
    </button>
  );
}
코드 역할
useState(0) 초기값 0으로 상태 선언
count 현재 렌더링에서 읽는 값
setCount 다음 상태를 지정하는 함수
previous => previous + 1 이전 상태를 기준으로 다음 값 계산
text
버튼 클릭 → setCount → 컴포넌트 다시 렌더링 → 바뀐 화면 반영

setCount를 호출한 직후 같은 함수에서 읽는 count는 현재 렌더링의 값입니다. 변수를 즉시 덮어쓰는 대입문처럼 생각하지 마세요.

useState처럼 use로 시작하는 React 기능을 Hook이라고 합니다. Hook은 컴포넌트나 사용자 정의 Hook의 최상위에서 호출합니다. 조건문이나 반복문 안에서 호출하지 않습니다. 공식 State 안내

STEP 07

Event — 클릭과 입력에 반응하기

사용자의 행동에 실행할 함수를 연결합니다.

jsx
function SaveButton() {
  function handleClick() {
    alert("저장 버튼을 눌렀습니다.");
  }

  return <button onClick={handleClick}>저장</button>;
}
작성법 의미
onClick={handleClick} 클릭할 때 실행할 함수 전달
onClick={() => handleDelete(id)} 클릭할 때 ID를 넣어 실행
onClick={handleClick()} 렌더링 중 즉시 실행하므로 이 용도에는 잘못된 작성

폼 제출에서는 event.preventDefault()로 브라우저의 기본 제출 동작을 막고 JavaScript로 처리할 수 있습니다. 공식 이벤트 안내

STEP 08

Input — 입력창과 State 연결

입력값을 React 상태로 관리하는 입력창을 만듭니다.

jsx
const [title, setTitle] = useState("");

<input
  value={title}
  onChange={(event) => setTitle(event.target.value)}
  placeholder="할 일을 입력하세요"
/>
  1. value={title}로 입력창에 현재 상태를 표시합니다.
  2. 사용자가 글자를 입력하면 onChange가 실행됩니다.
  3. event.target.value에서 새 입력값을 읽습니다.
  4. setTitle()로 상태를 바꾸면 입력창도 새 값을 표시합니다.
text
title 상태 → 입력창 value
    ↑             │
    └─ setTitle ← onChange

이 방식을 **제어 컴포넌트의 입력(controlled input)**이라고 합니다. value만 지정하고 값을 갱신하지 않으면 타이핑해도 입력값이 바뀌지 않습니다.

STEP 09

List — 배열을 화면에 표시

배열의 각 항목을 JSX로 바꾸면 목록을 만들 수 있습니다.

jsx
<ul>
  {todos.map((todo) => (
    <li key={todo.id}>{todo.title}</li>
  ))}
</ul>
  • map()은 각 할 일을 <li>로 변환합니다.
  • key는 React가 형제 항목을 구별하는 기준입니다.
  • DB ID처럼 고유하고 안정적인 값을 사용합니다.
  • 렌더링할 때마다 랜덤 key를 만들지 않습니다. 추가할 때 ID를 한 번 생성합니다.

목록이 비어 있을 때는 조건부로 안내를 표시할 수 있습니다.

jsx
{todos.length === 0 && <p>아직 할 일이 없습니다.</p>}

STEP 10

배열 수정 — 추가·완료·삭제

상태 배열을 직접 수정하지 않고 새 배열로 교체합니다.

추가: 펼치기

jsx
setTodos((previous) => [...previous, newTodo]);

완료 변경: map

jsx
setTodos((previous) =>
  previous.map((todo) =>
    todo.id === id
      ? { ...todo, completed: !todo.completed }
      : todo
  )
);

{ ...todo, completed: ... }는 기존 객체를 복사한 뒤 완료 여부만 바꿉니다.

삭제: filter

jsx
setTodos((previous) => previous.filter((todo) => todo.id !== id));
목적 사용할 방식 피할 직접 변경
추가 새 배열로 펼치기 todos.push(...)
항목 수정 map + 객체 복사 todo.completed = true
삭제 filter todos.splice(...)

React는 바뀐 상태를 받아 화면을 계산합니다. 새 배열과 객체를 만들어 갱신하면 이전 상태를 유지하면서 변경을 전달할 수 있습니다. 공식 배열 상태 안내

STEP 12

Spring과 연결하면 무엇이 달라질까?

React의 메모리 상태를 DB에 저장하려면 API가 필요합니다.

현재 브라우저 예제 서버 연결 후
임시 ID 생성 DB가 만든 ID 사용
state에 목록 추가 POST 요청 후 결과 반영
새로고침 시 초기화 GET 요청으로 DB 목록 조회
브라우저 입력 검증 Spring에서도 검증

기존 Spring의 /todos는 HTML을 반환합니다. 여기에 response.json()을 호출하면 JSON 파싱 오류가 납니다. 별도의 JSON API를 만들어야 합니다.

요청과 응답 약속

text
POST /api/todos
요청: { "title": "리액트 공부" }
응답: { "id": 1, "title": "리액트 공부", "completed": false }

GET /api/todos
응답: [{ "id": 1, "title": "리액트 공부", "completed": false }]

다음 함수는 위 API가 준비되었을 때 사용하는 연결 예시입니다.

js
async function createTodo(title) {
  const response = await fetch("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title }),
  });

  if (!response.ok) {
    throw new Error("저장하지 못했습니다.");
  }

  return response.json();
}
코드 역할
async / await 비동기 요청의 결과를 기다림
fetch HTTP 요청 전송
JSON.stringify JavaScript 객체를 JSON 문자열로 변환
response.ok HTTP 성공 여부 확인. fetch는 404·500만으로 reject되지 않음
response.json() 응답 JSON을 JavaScript 값으로 읽음

실제 저장 이벤트에서는 try/catch로 실패를 표시하고, 요청 중에는 저장 버튼을 비활성화합니다. 실패했을 때 입력을 지우지 않으면 다시 시도하기 쉽습니다.

TodoForm과 연결해서 이해하기

HTML 폼 방식 JSON API 방식
@ModelAttribute TodoForm @RequestBody TodoCreateRequest
폼 필드 입력 JSON 본문 입력
HTML 화면 응답 응답 DTO를 JSON으로 반환

React의 state는 브라우저 화면 상태이고, Spring의 DTO는 서버에 데이터를 전달하는 객체입니다. 서로 다른 위치에 있지만 같은 제목 값을 주고받을 수 있습니다.

React 개발 서버와 Spring은 포트가 달라 출처(origin)도 다릅니다. 개발 중에는 Vite의 /api 프록시를 구성하거나 서버에 필요한 CORS 설정을 해야 합니다. /api/todos라는 상대 주소는 현재 화면의 서버를 기준으로 요청됩니다. 이 가이드에는 API나 프록시를 실제 적용하지 않았습니다.

1. App.jsx — 할 일 등록·완료·삭제

Vite React 프로젝트의 src/App.jsx 전체를 교체합니다. 서버 없이 브라우저 상태로만 동작하므로 새로고침하면 초기화됩니다.

jsx
import { useState } from "react";
import "./App.css";

function TodoItem({ todo, onToggle, onDelete }) {
  return (
    <li className="todo-item">
      <label>
        <input
          type="checkbox"
          checked={todo.completed}
          onChange={() => onToggle(todo.id)}
        />
        <span className={todo.completed ? "completed" : ""}>
          {todo.title}
        </span>
      </label>
      <button type="button" onClick={() => onDelete(todo.id)}>
        삭제
      </button>
    </li>
  );
}

export default function App() {
  const [title, setTitle] = useState("");
  const [todos, setTodos] = useState([]);
  const [error, setError] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    const trimmedTitle = title.trim();

    if (!trimmedTitle || trimmedTitle.length > 100) {
      setError("할 일을 1~100자로 입력해 주세요.");
      return;
    }

    const newTodo = {
      id: crypto.randomUUID(),
      title: trimmedTitle,
      completed: false,
    };

    setTodos((previous) => [...previous, newTodo]);
    setTitle("");
    setError("");
  }

  function handleToggle(id) {
    setTodos((previous) =>
      previous.map((todo) =>
        todo.id === id
          ? { ...todo, completed: !todo.completed }
          : todo
      )
    );
  }

  function handleDelete(id) {
    setTodos((previous) => previous.filter((todo) => todo.id !== id));
  }

  return (
    <main className="todo-app">
      <h1>나의 할 일</h1>
      <p>등록하고, 완료하고, 삭제하며 React를 익혀 보세요.</p>

      <form onSubmit={handleSubmit}>
        <label htmlFor="title">새 할 일</label>
        <div className="input-row">
          <input
            id="title"
            value={title}
            onChange={(event) => setTitle(event.target.value)}
            maxLength={100}
            placeholder="예: 리액트 공부하기"
            aria-describedby="input-error"
            aria-invalid={Boolean(error)}
          />
          <button type="submit">추가</button>
        </div>
        <p id="input-error" role="alert">{error}</p>
      </form>

      <p aria-live="polite">총 {todos.length}개의 할 일</p>
      {todos.length === 0 && <p>아직 할 일이 없습니다.</p>}

      <ul className="todo-list">
        {todos.map((todo) => (
          <TodoItem
            key={todo.id}
            todo={todo}
            onToggle={handleToggle}
            onDelete={handleDelete}
          />
        ))}
      </ul>
    </main>
  );
}

읽는 순서

  1. App이 title, todos, error 세 상태를 관리합니다.
  2. 입력한 title로 새 할 일 객체를 생성합니다.
  3. setTodos로 목록을 갱신합니다.
  4. TodoItem은 할 일과 두 이벤트 함수를 props로 받습니다.
  5. 자식은 상태를 직접 바꾸지 않고 부모의 함수를 호출합니다.

crypto.randomUUID()는 localhost 또는 HTTPS 같은 보안 컨텍스트에서 사용합니다. 위 Vite 로컬 실행 환경에서 사용할 수 있습니다.
