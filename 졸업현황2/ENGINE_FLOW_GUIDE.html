1. OCR 결과의 공백 처리

요구사항과 문제

같은 과목이어도 JAVA, JAVA , J A V A처럼 공백이 다르면 문자열 비교가 실패할 수 있습니다. 과목을 찾지 못하거나 같은 과목을 두 번 계산할 수 있습니다.

해결 방법: 공백을 목적에 따라 나눠 처리

한 줄을 분석할 때는 앞뒤 공백만 제거합니다.

text = text.strip()
# "  JAVA 3 A+  " → "JAVA 3 A+"

이 시점에는 과목명·학점·성적을 구분하는 중간 공백이 필요합니다. 처음부터 모든 공백을 지우면 JAVA3A+가 되어 필드를 구분하기 어렵습니다.

과목명을 분리한 다음, 비교용 이름에서는 모든 공백을 제거합니다.

def normalize(value):
    return re.sub(
        r'\s+',
        '',
        unicodedata.normalize('NFKC', str(value or ''))
    ).casefold()
코드담는 값 또는 역할
value정리할 원래 과목명
value or ''비어 있는 값이면 빈 문자열 사용
str(...)문자열로 변환
unicodedata.normalize('NFKC', ...)전각 영문 등 호환 문자 표현 통일
re.sub(r'\s+', '', ...)공백·탭·줄바꿈 제거
.casefold()대소문자 차이를 줄여 비교
" J A V A " → "java"
"ＪＡＶＡ"   → "java"

반환값은 검색·비교용 키입니다. 화면에 표시할 과목명을 모두 소문자로 바꾸는 것은 아닙니다.

2. 대소문자 처리

요구사항과 문제

JAVA, Java, java를 같은 과목으로 비교해야 합니다. 성적도 b0와 B0를 같은 표기로 처리해야 합니다.

해결 코드

key = normalize(name)
# name = "Java" → key = "java"

grade = str(row.get('성적', '')).strip().upper()
# " b0 " → "B0"

name은 과목명, key는 정규화한 검색 키, row는 현재 과목 딕셔너리, grade는 정리한 성적입니다. 과목명은 casefold, 성적은 upper로 통일합니다.

해결 범위

B0의 숫자 0과 BO의 영문 O는 다릅니다. upper는 BO를 B0로 고쳐 주지 않습니다. 현재 코드는 알 수 없는 성적을 임의 통과시키지 않고 검토하도록 합니다.

3. 문자열을 계산 가능한 과목 데이터로 변환

요구사항과 문제

OCR의 JAVA 3 A+는 하나의 문자열입니다. 과목명·학점·성적을 분리하고 학점을 숫자로 바꿔야 계산할 수 있습니다.

해결 코드

match = pattern.fullmatch(text)
if match:
    name, credits, grade = match.groups()

pattern은 행의 형태를 검사하는 정규표현식 객체입니다. match는 일치 결과이며, 맞지 않으면 None입니다. 추출 직후 name='JAVA', credits='3', grade='A+'는 모두 문자열입니다.

# 실제 코드의 핵심 부분을 축약한 예시
rows.append({
    '과목명': name,
    '학점': float(credits),
    '성적': grade.upper(),
    '확인': False,
})

rows는 여러 과목을 담는 리스트이고, {...}는 한 과목을 담는 딕셔너리입니다. append는 딕셔너리 하나를 리스트 끝에 넣습니다. float는 문자 학점을 숫자로 바꿉니다.

"3" + "3"   # "33"
3.0 + 3.0   # 6.0

확인=False로 시작하므로 인식된 과목이 바로 인정되는 것은 아닙니다. 실제 후보에는 이수구분·인식신뢰도·메모도 저장합니다.

rejected.append({
    'text': text,
    'reason': '과목명·학점·성적 열을 확인하세요.',
})

해석할 수 없는 줄은 rejected에 원문과 사유를 남깁니다. 파서는 (rows, rejected) 두 목록을 반환합니다.

4. 교육과정에서 일치하는 과목 찾기

요구사항과 문제

어느 이수구분에 속하는 과목인지 알아야 전공필수·전공선택·교양 학점을 구분하여 합산할 수 있습니다.

해결 코드

def catalog_index(profile):
    return {
        normalize(c['name']): c
        for c in profile['courses']
    }

key = normalize(name)
course = catalog.get(key)
변수무엇을 담나요?예시
profile선택한 연도·트랙의 교육과정courses·minimums 등을 가진 dict
c교육과정 목록에서 꺼낸 한 과목JAVA 기준 정보
catalog과목명 → 과목 정보 검색 사전{'java': {...}}
key정규화한 과목명'java'
course찾은 기준 과목 정보dict 또는 None
catalog = {
    'java': {
        'name': 'JAVA',
        'credits': 3,
        'category': '전공필수',
    }
}

정확히 일치하면 기준 이수구분을 제안합니다. suggest에서 비슷한 이름만 찾았다면 후보로 안내하고 자동으로 대체 인정하지 않습니다.

5. 계산 전 입력 검증

요구사항과 문제

사용자가 확인을 체크했더라도 잘못 입력한 학점·성적·이수구분이 남아 있을 수 있습니다. 이런 행을 그대로 합산하면 실제보다 많은 학점을 인정할 수 있습니다.

순서검사 내용실패 시 처리
1과목명이 있는가?빈 행은 건너뜀
2원문 확인이 True인가?issues에 기록
3유효한 이수구분인가?issues에 기록
4유한한 숫자이고 0 < 학점 ≤ 30인가?issues에 기록
5F·미이수·수강중 등인가?excluded에 기록
6허용된 통과 성적인가?알 수 없으면 issues에 기록
7교육과정의 학점·구분과 같은가?불일치하면 합산하지 않음
8이미 인정한 과목인가?중복 검사
# 오류 메시지를 생략한 핵심 조건
course = catalog.get(key)
if course and (
    credits != float(course['credits'])
    or category != course['category']
):
    issues.append('교육과정과 학점 또는 구분이 다릅니다.')
    continue

입력: JAVA / 30학점 / 기초교양
기준: JAVA /  3학점 / 전공필수
→ 불일치 안내 → 현재 행 합산 안 함 → 다음 행 검사

credits는 현재 과목의 숫자 학점, category는 입력 이수구분입니다. continue는 현재 행의 남은 처리를 건너뛰고 다음 행으로 넘어갑니다. 교육과정에 없는 전공 과목도 공식 확인을 요구합니다.

6. 중복 과목 제거

요구사항과 문제

겹치는 사진이나 반복 입력으로 JAVA 3 A+와 java 3 A+가 함께 들어오면 6학점으로 잘못 더해질 수 있습니다.

해결 코드

key = normalize(name)
if key in accepted:
    old = accepted[key]
    if old['학점'] != credits or old['이수구분'] != category:
        issues.append('중복 내역의 학점 또는 구분이 다릅니다.')
    else:
        excluded.append(f'{name}: 중복 취득은 1회만 계산')
    continue

오류 메시지를 축약한 설명용 코드입니다. accepted는 검사를 통과한 과목을 저장한 사전, old는 이미 저장된 동일 과목의 정보입니다.

첫 번째 JAVA → key='java' → accepted에 없음 → 저장·합산
두 번째 java → key='java' → accepted에 있음 → 중복 처리

원본 행을 삭제하는 방식이 아니라 합산 대상에서 제외하는 방식입니다. 학점·구분이 다른 중복은 사용자가 정리하도록 issues에 남깁니다. 이름이 바뀐 동일 과목은 공식 대응표 없이는 완전히 구분할 수 없습니다.

7. 핵심 로직: 검증된 과목만 누적

요구사항

검사를 통과한 과목만 전공필수·전공선택·교양 등의 누계에 반영해야 합니다.

totals = {c: 0.0 for c in CATEGORIES}

# 모든 검사와 중복 처리를 통과한 뒤 실행
accepted[key] = {
    '과목명': name,
    '학점': credits,
    '이수구분': category,
    '성적': grade,
}
totals[category] += credits

초기화 부분의 c는 이수구분 문자열입니다. totals는 구분별 숫자 누계를 담는 딕셔너리이고, accepted는 인정 과목 정보를 담는 딕셔너리입니다.

category = '전공필수'
credits = 3.0
전공필수 누계: 0.0 → 3.0 → 6.0 → 9.0 …

+=는 기존 값에 현재 학점을 더해 다시 저장합니다. 검토 문제가 있는 행이 섞여 있으면 화면의 총학점은 유효한 행만의 부분 합계일 수 있습니다.

8. 계산 공식

① 이수구분별 인정학점

이수구분별 인정학점
= 검증을 통과하고 중복이 아닌 해당 구분 과목들의 학점 합

② 총 취득학점

totals['총학점'] = sum(totals.values())

총 취득학점 = 전공필수 + 전공선택 + 전공심화
           + 기초교양 + 나사렛교양 + 핵심교양 + 소양교양
           + 자율선택

미분류는 앞선 검사에서 제외되어 합계에 기여하지 않습니다. 이 줄은 교양합계·전공합계 같은 파생 합계를 사전에 추가하기 전에 실행합니다.

③ 교양·전공 합계

교양합계 = 기초교양 + 나사렛교양 + 핵심교양 + 소양교양
전공합계 = 전공필수 + 전공선택 + 전공심화

④ 부족학점

# 수식을 읽기 쉽게 쓴 설명용 변수 이름
부족학점 = max(0, 필요학점 - 인정학점)

필요 127 / 인정 120 → 부족 7학점
필요 127 / 인정 130 → 부족 0학점

max(0, ...)은 초과 이수한 경우 부족학점을 음수가 아닌 0으로 표시합니다.

⑤ 전공심화 처리

totals['전공선택'] += totals['전공심화']

현재는 전공심화를 전공선택 최소학점에도 포함한다는 가정입니다. 총학점·전공합계를 먼저 계산한 뒤 이 처리를 수행하므로 총학점에 두 번 더해지지 않습니다. 실제 학과의 인정 방식은 별도 확인해야 합니다.

9. 최종 상태 결정

요구사항

학점이 충분하더라도 입력 문제나 의무 과목 누락이 있다면 이를 먼저 알려야 합니다.

# 실제 중첩 조건식을 이해하기 쉽게 풀어 쓴 설명용 코드
if issues:
    status = '입력 검토 필요'
elif missing or any(c['부족학점'] for c in checks):
    status = '입력 기준 미충족'
else:
    status = '입력한 학점·지정 과목 기준 충족 (공식 요건 확인 대기)'
변수내용
issues입력 오류·확인 요청 목록
missing사용자가 지정한 의무 과목 중 인정 내역에 없는 이름 목록
checks항목별 필요·인정·부족학점 딕셔너리 목록
cany 내부에서는 checks에서 꺼낸 결과 딕셔너리 하나
status최종 결과 문구
입력 문제가 있는가? → 예: 입력 검토 필요
        ↓ 아니오
의무 과목 누락 또는 부족학점이 있는가? → 예: 입력 기준 미충족
        ↓ 아니오
입력 조건 충족 / 공식 요건 확인 대기

교육과정에 있는 모든 전공필수 과목을 자동으로 의무 이수로 확정하지 않습니다. missing은 사용자가 학과 확인 후 지정한 mandatory를 기준으로 만듭니다.

10. 해결한 문제와 남은 한계

문제현재 해결 방법남은 한계
공백·대소문자로 비교 실패비교용 이름 정규화OCR 철자 오류까지 수정하지 않음
문자 학점을 잘못 계산float 변환·유효성 검사원문 오인식은 사용자 확인 필요
동일 과목 중복 합산정규화한 이름으로 중복 검사이름 변경·대체과목은 공식 자료 필요
F·수강중 과목 인정성적 집합으로 제외학교별 성적 제도 확인 필요
학점·이수구분 오입력교육과정과 대조미등록 교양은 사용자 검토에 의존
해석 실패 행이 조용히 누락rejected에 원문·사유 보존OCR이 아예 탐지하지 못한 줄은 원문 대조 필요
학점 충족을 졸업 확정으로 오해공식 요건 확인 대기 표시졸업시험·논문·인증 등 별도 확인 필요

발표할 때 설명하는 문장

“OCR 결과를 바로 계산하지 않고, 먼저 과목 정보를 구조화하고 이름을 정규화합니다. 이후 사용자가 확인한 내역에 대해 성적·학점·교육과정·중복을 검증하고, 통과한 과목만 합산합니다. 마지막으로 최소학점과 비교하여 부족분과 추가 확인 사항을 제공합니다.”
