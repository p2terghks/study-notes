rule_login_failure_burst()

로그인 events → 그룹별 실패 집중 탐지
R/03_detect.R · 원본 32–47행
32rule_login_failure_burst <- function(ev, threshold = 3, window_min = 60) {33  ev |>34    filter(event_name == "ConsoleLogin", login_result == "Failure", !is.na(event_time)) |>35    group_by(id, technique, principal) |>36    summarise(37      n_total = n(),38      # 각 실패 시각 t에서 [t, t + window] 안에 들어오는 실패 수의 최댓값39      n       = max(vapply(event_time, \(t) sum(event_time >= t & event_time <= t + window_min * 60), numeric(1))),40      event_time = min(event_time),41      source_ip  = paste(unique(source_ip), collapse = ","),42      event_name = "ConsoleLogin", .groups = "drop") |>43    filter(n >= threshold) |>44    mutate(severity = if_else(n >= 5, "high", "medium"),45           detail = sprintf("%d분 안에 콘솔 로그인 실패 %d회 (전체 실패 %d회)", window_min, n, n_total)) |>46    finalize()47}
  1. ConsoleLogin·Failure 조건과 유효한 시각을 만족하는 행만 고릅니다.
  2. group_by(id,technique,principal)는 같은 시나리오·라벨·주체끼리 계산하도록 묶습니다.
  3. n_total=n()은 전체 실패 수입니다. vapply()는 각 실패 시각 t에서 [t,t+60분] 범위의 실패 수를 하나씩 계산하고 숫자 하나라는 반환 형태를 지정합니다.
  4. event_time>=t & event_time<=t+window_min*60은 논리 벡터입니다. sum()은 TRUE를 1로 세고, max()는 그중 최댓값을 선택합니다.
  5. summarise()는 대표 시각을 그룹 최초 시각, IP를 중복 제거 후 쉼표로 합친 값으로 기록합니다. .groups="drop"으로 그룹을 해제합니다.
  6. 최댓값 n이 threshold 이상일 때만 남깁니다. n>=5이면 high, 그 외 medium입니다. sprintf()는 숫자를 설명 문자열에 끼워 넣습니다.
정확히 구분하기

집중 구간을 정확히 찾았어도 출력 event_time과 source_ip는 그룹 전체 요약입니다. 임계값 threshold를 바꿔도 high 기준 5는 별도로 고정되어 있습니다.

rule_multi_ip()

로그인 events → IP가 바뀐 현재 이벤트
R/03_detect.R · 원본 51–64행
51rule_multi_ip <- function(ev, window_min = 10) {52  ev |>53    filter(event_name == "ConsoleLogin",54           user_type %in% c("Root", "IAMUser"), str_detect(source_ip, IPV4), !is.na(event_time)) |>55    arrange(id, principal, event_time) |>56    group_by(id, technique, principal) |>57    mutate(prev_ip = lag(source_ip),58           gap = as.numeric(difftime(event_time, lag(event_time), units = "mins"))) |>59    ungroup() |>60    filter(!is.na(prev_ip), prev_ip != source_ip, gap >= 0, gap <= window_min) |>61    mutate(severity = if_else(user_type == "Root", "high", "medium"),62           detail = sprintf("%.1f분 간격으로 IP 변경 (%s -> %s)", gap, prev_ip, source_ip)) |>63    finalize()64}
  1. Root/IAMUser·IPv4 모양·ConsoleLogin·유효한 시각을 먼저 선택합니다.
  2. arrange()로 시간순을 만든 후 시나리오·주체별로 그룹을 나눕니다.
  3. lag(source_ip)는 직전 행 IP, lag(event_time)은 직전 시각을 가져옵니다. 그룹 첫 행은 이전 값이 없어 NA입니다.
  4. difftime(...,units="mins")는 시간 차이이고 as.numeric()이 분 단위 숫자로 바꿉니다.
  5. ungroup()으로 그룹을 풀고, 이전 IP가 존재하고 IP가 다르며 0~window_min분일 때만 남깁니다.
  6. Root는 high, IAMUser는 medium입니다. detail에는 이전 IP와 현재 IP, 시간 간격을 넣습니다.
정확히 구분하기

성공 로그인에 한정하지 않습니다. IPv6는 제외하고 IPv4 정규식은 0~255 범위를 검사하지 않습니다. IP 변경을 세션 탈취로 확정하지 않습니다.

rule_login_without_mfa()

로그인 events → MFA 없는 성공 로그인
R/03_detect.R · 원본 68–75행
68rule_login_without_mfa <- function(ev) {69  ev |>70    filter(event_name == "ConsoleLogin", login_result == "Success", mfa_used == "No",71           user_type %in% c("Root", "IAMUser")) |>72    mutate(severity = if_else(user_type == "Root", "high", "medium"),73           detail = sprintf("MFA 없이 %s 콘솔 로그인 성공", user_type)) |>74    finalize()75}
  1. ConsoleLogin, Success, MFAUsed="No", Root/IAMUser 조건을 모두 만족해야 합니다. filter() 안의 쉼표는 조건들의 AND입니다.
  2. MFA 값이 NA이면 해당 조건이 TRUE가 아니므로 filter()에서 제외됩니다.
  3. Root는 high, IAMUser는 medium으로 구분하고 finalize()로 공통 형식을 반환합니다.
정확히 구분하기

AssumedRole은 대상에 없습니다. MFA 미사용과 공격 성공은 같은 의미가 아닙니다. R03에는 시각 결측값을 제외하는 별도 조건이 없습니다.

발표에서 설명할 평가와 한계

대응 규칙이 한 번이라도 발동한 시나리오를 detected로 계산합니다. 모든 공격 이벤트를 잡아야 한다는 기준은 아닙니다. 독립적인 검증 데이터와 정상 로그가 없어 실환경 정확도·오탐률을 주장할 수 없습니다.

현재 콘솔 로그인만 대상으로 바뀌었으므로 이전 전체 분석의 24/24·151건을 새 결과로 사용하지 않습니다. 새 결과는 패키지 설치 후 실제 실행에서 확인해야 합니다.
