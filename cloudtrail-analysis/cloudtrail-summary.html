먼저: 이 프로그램이 하는 일

CloudTrail은 AWS에서 어떤 작업이 일어났는지 기록한 로그입니다. 그중 eventName이 ConsoleLogin인 항목이 콘솔 로그인 시도 기록입니다. 이 프로그램은 준비한 JSON 파일에서 그 항목만 골라 시간·사용자·IP·결과의 표를 만들고 CSV로 저장합니다.

파일 → 문자열 → R 리스트 → 로그인 이벤트 선택 → 표 → CSV
헷갈리기 쉬운 점

공격을 자동 판단하거나 반복 실패를 경고하는 프로그램은 아닙니다. 성공과 실패 로그인 기록을 모두 찾아 보여줍니다. AWS에 연결해 로그를 가져오지는 않습니다.

2. $ · [ ] · [[ ]]를 구분하기

x <- list(userIdentity = list(userName = "demo-user"))
x$userIdentity$userName  # "demo-user"
values <- c("first", "second")
values[[1]]              # "first"
values[c(TRUE, FALSE)]   # "first"

$는 이름을 따라 안으로 들어갑니다. [[1]]은 첫 번째 원소 자체를 꺼냅니다. R의 첫 번째 번호는 1입니다. [ ]는 위치나 TRUE/FALSE로 원소를 선택할 때 사용하고 표에는 [행, 열]을 씁니다.

output[c(2, 1), , drop = FALSE]  # 두 번째 행, 첫 번째 행 순서 + 모든 열
헷갈리기 쉬운 점

CSV는 파일 형식이고 data.frame은 R 메모리 안의 자료구조입니다. 표를 만들었다고 파일에 저장되는 것은 아닙니다. write.csv()를 호출해야 디스크 파일이 생깁니다.

4. 처음 실행하는 방법

R을 설치한 컴퓨터에서 한 번만 아래 패키지를 설치합니다. 패키지는 R에 기능을 추가하는 도구 모음이며 jsonlite는 JSON을 해석합니다. 아래 명령은 R 콘솔에 입력합니다.

install.packages("jsonlite")

그다음 login_records.R과 입력 로그 파일이 있는 폴더에서 터미널을 열고 실행합니다. Rscript는 터미널에서 R 파일을 실행하는 명령입니다.

Rscript login_records.R logs.json
Rscript login_records.R logs.json output/logins.csv

첫 명령은 기본 output/login_records.csv에, 둘째는 지정한 output/logins.csv에 저장합니다. logs.json은 사용자가 준비한 실제 파일 이름으로 바꾸세요. 경로에 공백이 있으면 따옴표로 감쌉니다.

Rscript "login_records.R" "my logs.json" "output/my logins.csv"
헷갈리기 쉬운 점

입력과 출력은 다른 경로로 지정하세요. 출력 파일이 이미 있으면 덮어씁니다. 원본 파일을 직접 수정하지는 않지만 같은 경로를 출력으로 지정하면 덮어쓸 수 있습니다.

핵심 코드를 세 문장으로

read_events(): 파일 문자를 JSON 구조로 해석해 이벤트 목록을 만듭니다.

login_records(): 목록에서 로그인만 골라 네 열의 표로 정리합니다.

write.csv(): 그 표를 파일로 저장합니다. print()와 cat()은 화면에 보여주는 역할입니다.

records <- login_records(read_events(args[[1]]))

이 줄은 안쪽부터 읽습니다. args[[1]]의 파일 경로 → read_events()의 이벤트 목록 → login_records()의 표 → records 변수 순서입니다.

자주 헷갈리는 질문

질문답
text_value()의 x는 고정된 값인가요?호출할 때마다 전달받는 값입니다. 이름·IP·시각 각각이 x가 될 수 있습니다.
return()이 없는데 결과가 나오나요?R 함수는 마지막 표현식의 결과를 자동 반환합니다. return()은 중간에서 바로 끝내고 싶을 때도 씁니다.
Filter와 lapply는 무엇이 다른가요?Filter는 조건에 맞는 원소만 선택합니다. lapply는 원소마다 작업해 결과를 리스트로 모읍니다.
왜 먼저 파일 전체를 읽고 다시 줄마다 읽나요?일반 JSON 문서와 한 줄당 한 문서인 NDJSON 모두를 지원하기 때문입니다. 한 줄 실패 후에도 계속 진행하는 방식은 아닙니다.
c()와 rbind()가 둘 다 합치는 것 아닌가요?여기서 c()는 이벤트 목록을 이어 붙이고 rbind()는 같은 열의 표를 위아래로 붙입니다. 반환 자료형이 다릅니다.
source()와 Rscript는 같은가요?source()는 R 코드 안에서 다른 파일을 읽어 실행합니다. Rscript는 터미널에서 스크립트를 실행합니다. 이 코드의 실행부 조건은 source할 때 자동 파일 처리를 피하게 합니다.
NA를 빈칸으로 저장하면 에러가 사라지나요?NA는 누락값입니다. CSV에서 빈칸으로 보이게 저장할 뿐, 빠진 정보를 복원하지 않습니다.
모든 로그인 방식의 기록을 찾나요?입력에 있는 eventName=ConsoleLogin만 찾습니다. 다른 API·SSO 관련 이벤트 전체를 포괄한다고 해석하면 안 됩니다.
시간을 날짜형으로 바꾸나요?현재는 UTC ISO 시각 문자열을 정렬합니다. 서로 다른 시간대·표현이 섞이면 별도 시간 파싱이 필요합니다.

검증한 범위

가상 데이터로 Records 문서·배열·단일 이벤트·NDJSON·빈 입력·로그인 없는 입력·잘못된 JSON을 검사했습니다. 성공/실패 유지, 시각 순서, 사용자 ARN 대체, 누락 필드와 CSV 저장도 실제 R 실행으로 확인했습니다.

실제 계정에서 로그를 수집하거나 공격 판정 성능을 측정한 것은 아닙니다. 입력 전체를 메모리에 읽고 중복 이벤트는 제거하지 않습니다.
