01. 먼저 보는 실행 순서

파일 경로→read_events()→event_list()→이벤트 목록→login_records()→로그인 4열 표→CSV / 실패 집계·그래프

source()는 함수 정의를 불러옵니다. 함수를 준비한 것과 호출해 실행한 것은 다릅니다. 다음 두 줄은 정의를 불러오고, 그 뒤의 호출들이 실제 데이터를 처리합니다.

source("login_records.R")
source("failure_charts.R")
events <- read_events("data/logs.json")
records <- login_records(events)
plot_login_failures(records)
save_failure_chart(records, "output/login_failures.png")

프로젝트 폴더를 작업 폴더로 선택하고 data/logs.json에 준비한 입력 파일을 넣습니다. 경로는 예시이며 로그는 저장소에 포함되지 않습니다. CSV·PNG를 함께 저장하려면 터미널에서 Rscript run_analysis.R data/logs.json output을 실행합니다.

03. 반복문·익명함수·오류 처리의 실행 순서

for: 한 줄씩 읽으며 누적

lines = c(첫째줄, 둘째줄, 셋째줄)
i = 1 → 첫째줄 해석 → event_list(item) → result에 추가
i = 2 → 둘째줄 해석 → event_list(item) → result에 추가
i = 3 → 셋째줄 해석 → event_list(item) → result에 추가
반복 종료 → result 반환

이 반복은 파일 전체를 JSON 하나로 해석하는 첫 시도가 실패했을 때만 실행됩니다. 중간 줄이 잘못됐다면 그 줄의 stop()에서 끝나고 다음 줄을 처리하지 않습니다.

Filter와 lapply: 같은 반복처럼 보여도 목적이 다름

events   = [로그인 실패, 일반 API, 로그인 성공]
Filter   → [로그인 실패, 로그인 성공]  # 원본을 선택
lapply   → [한 행 표, 한 행 표]        # 각각 변환
rbind    → 2행 × 4열 표                # 세로로 연결

tryCatch와 on.exit: 언제 실행되는가?

error = function(e) ...는 시도한 표현식이 오류를 냈을 때 실행됩니다. 반면 on.exit(...)는 해당 함수가 끝날 때 정리 작업을 실행합니다. 파일 전체 해석 오류는 NULL로 바꿔 재시도하지만, 한 줄 해석 오류는 stop()으로 중단합니다. 두 오류 경로를 구분해야 합니다.

다음은 설명용 가상 이벤트 네 개입니다. 실제 수집 데이터가 아닙니다.

이벤트시각(UTC)결과처리
A · ConsoleLogin2026-11-01 09:15Failure표에 남고 11월 1일·09시 실패 각각 +1
B · ConsoleLogin2026-11-01 09:30Success표에 남지만 실패 집계 제외
C · ConsoleLogin잘못된 문자열Failure표에는 남음 / total +1 / invalid_time +1 / 막대 제외

입력 이벤트 4개

→ 실패 표 2행(A, C)
→ total = 2 / invalid_time = 1
→ 날짜별 막대 합계 = 1 / 시간대별 막대 합계 = 1

total은 시각이 잘못된 실패도 포함합니다. 따라서 막대 합계는 total - invalid_time입니다. 사용자명이 누락되면 ARN을 쓰며, 둘 다 없으면 NA를 유지합니다.

발표용 설명과 질문

“여러 형태의 CloudTrail JSON을 읽어 이벤트 목록으로 통일한 뒤, ConsoleLogin 이벤트만 네 열의 표로 만듭니다. 이후 실패 결과만 골라 UTC 날짜와 시각대별 횟수를 세고, RStudio 그래프와 CSV·PNG로 제공합니다. 조건문은 빈 입력·누락 필드·실패 여부·작은 그래프 창을 처리하고, 반복문과 lapply는 각 줄과 이벤트를 순서대로 처리합니다.”

왜 &와 &&를 다르게 쓰나요?

실패 표를 고를 때는 여러 행의 논리 벡터를 원소별로 결합해야 하므로 &를 씁니다. Filter 내부에서는 이벤트 한 개의 조건을 순서대로 검사하며, list가 아니면 $ 검사를 생략하려고 &&를 씁니다.

왜 return() 없는 함수도 값이 나오나요?

R 함수는 마지막으로 평가한 표현식을 자동 반환합니다. event_list의 마지막 x, read_events의 마지막 result가 그 예입니다. return()은 중간에 즉시 반환하고 종료할 때 유용합니다.

실패 82건이 공격 82건인가요?

아닙니다. 공개 보안 테스트 로그 90건에서 실패 82건·성공 8건을 확인한 결과이며 중복 이벤트도 포함합니다. 별도 eventID 중복 제거 입력은 43건(실패 39·성공 4)입니다. 현재 코드는 공격 여부를 판정하거나 자동 중복 제거하지 않습니다.

왜 Source만 누르면 그래프가 없나요?

함수 파일을 source하면 정의가 준비됩니다. 데이터를 읽고 plot_login_failures(records)를 실제로 호출해야 합니다. run_analysis.R는 터미널 인자를 받는 실행 파일입니다.

작은 창 오류는 어떻게 해결했나요?

두 그림을 나눈 다음 장치 높이를 확인하고 작은 창에서는 여백 단위 mex와 글자 크기 cex를 줄입니다. 단순히 cex만 먼저 줄이면 mfrow 설정으로 초기화될 수 있습니다. 아주 작은 창은 넓히거나 Zoom을 사용해야 합니다.

지원 형식은 Records 문서·이벤트 배열·단일 이벤트·NDJSON입니다. 파일 전체를 메모리에 읽으며, 표의 시간 정렬은 원본 UTC ISO 문자열의 같은 형식을 전제로 합니다. 실제 입력 로그와 사용자·IP가 있는 CSV는 공개하지 않습니다. 집계와 검증 결과의 자세한 출처는 프로젝트 상세 설명에서 확인하세요.
